## 1. 产品定位

贷中风险预警助手是众安信科乾策平台（X-Nexus）信贷AI智能体矩阵中的 **Agent4**，定位于贷后监控环节——对存量授信客户进行持续风险扫描，通过规则引擎（22条规则、6大类别）+ LLM双通道发现风险信号，以红/黄/绿三级信号灯直观呈现预警结果，并生成个性化处置建议。

**一句话定位**：基于规则引擎+LLM双通道的存量信贷客户实时风险预警与智能处置系统。

**核心价值**：将银行贷后管理从"定期人工排查"升级为"实时智能预警+自动处置建议"，将风险发现周期从季度级缩短到天级。

**差异化前端元素**：信号灯UI（红黄绿灯动画）是整个智能体矩阵中唯一具有差异化的前端组件，通过红/黄/绿脉冲动画直观传达风险等级，是本Agent的视觉标识，必须保留。

**现有代码基础**：
- 预警引擎（alert_engine.py）：11条规则、5个类别 → 改造扩展到22条规则、6个类别
- 趋势分析器（trend_analyzer.py）：纯正则实现，较弱 → 改造接入LLM
- 处置建议（disposition.py）：19个预设模板 → 改造为LLM个性化生成+模板fallback
- 信号灯UI（app.py）：红黄绿灯动画 → 保留并增强

### 场景1：华联精密制造有限公司 — 红灯预警

**企业画像**：注册资本5000万，主营汽车零部件精密加工，授信余额3200万，贷款期限2024.06-2026.06。

**触发信号**（按时间线排列）：

| 时间 | 风险事件 | 预警规则 | 级别 |
|------|---------|---------|------|
| 2025-09 | 营业收入同比下降42%，连续两季度下滑 | FIN-001 营收下滑 | 🔴 红 |
| 2025-10 | 净利润转负，亏损680万元 | FIN-002 利润恶化 | 🔴 红 |
| 2025-11 | 被起诉：合同纠纷标的额1200万元 | LAW-001 涉诉预警 | 🔴 红 |
| 2025-11 | 网传"华联精密大规模裁员"、"核心客户转移订单" | NEW-001 负面舆情 | 🟡 黄 |
| 2025-12 | 应收账款周转天数从45天恶化至92天 | FIN-003 周转恶化 | 🟡 黄 |
| 2026-01 | 资产负债率升至78.3%（阈值70%） | FIN-004 杠杆超限 | 🟡 黄 |
| 2026-01 | 主要客户（占营收35%）公告进入重整 | REL-001 关联方风险 | 🔴 红 |

**综合评级**：🔴 红灯 — 多维度风险叠加，建议立即启动贷后处置流程。

**预期处置建议**（LLM生成）：
- 紧急：48小时内联系企业核实经营状况，要求补充近3个月银行流水
- 紧急：启动诉讼资产保全评估，关注1200万涉诉案件进展
- 高优：要求追加抵押物或保证人，弥补关联方风险敞口
- 常规：下调内部风险评级至"关注类"，增加贷后检查频率至月度

### 4.2 信号灯仪表盘（保留+增强）

**保留**：
- 红/黄/绿三灯布局
- CSS脉冲动画（当前状态灯呼吸式闪烁）
- idle（灰色）→ running（蓝色旋转）→ 结果色（红/黄/绿）状态流转

**新增**：
- 灯下方显示统计摘要：触发规则数、最高级别、最新信号时间
- running状态增加进度文字："正在扫描财务数据…" → "正在检索舆情…" → "正在生成处置建议…"

### 4.3 预警信号时间线（新增）

- 按时间倒序排列的风险事件卡片流
- 每张卡片包含：时间、风险等级色标、规则编号、事件摘要、数据来源标注
- 红色卡片带左侧红色竖条，黄色卡片带左侧橙色竖条
- 点击卡片可展开查看原始数据/证据

### 4.4 趋势分析折线图（新增）

- 使用Plotly生成交互式折线图（Gradio原生支持）

- 默认展示：营业收入、净利润、资产负债率三条线
- 阈值线以红色虚线标注（如负债率70%）
- 异常点（触发预警的数据点）用红色/橙色标记并标注

### 4.5 处置建议卡片（新增）

- 卡片式布局，每条建议一张卡片

- 卡片可勾选，标记为"已执行"/"已忽略"（仅前端状态，Demo用）

## 6. 数据模型

### 6.1 AlertSignal — 单条预警信号

```python
@dataclass
class AlertSignal:
    rule_id: str           # 规则编号，如 "FIN-001"
    rule_name: str         # 规则名称，如 "营收下滑"
    category: str          # 类别：financial / legal / business / industry / relation / news
    level: str             # "red" / "yellow" / "green"
    trigger_time: str      # 触发时间，如 "2025-09"
    summary: str           # 事件摘要，如 "营业收入同比下降42%"
    evidence: str          # 原始数据/证据来源
    metric_value: float    # 触发指标值（如42.0代表下降42%）
    threshold: float       # 阈值（如30.0代表30%）
```

### 6.2 AlertReport — 预警报告

```python
@dataclass
class AlertReport:
    enterprise_name: str
    report_date: str
    overall_level: str                 # "red" / "yellow" / "green"
    signals: list[AlertSignal]         # 全部预警信号
    red_count: int
    yellow_count: int
    trend_analysis: TrendAnalysis      # 趋势分析结果
    disposition_plan: DispositionPlan  # 处置建议
    llm_risk_summary: str             # LLM风险综述
    scan_duration_sec: float          # 扫描耗时
```

### 6.3 TrendItem — 趋势数据点

```python
@dataclass
class TrendItem:
    metric_name: str      # 指标名：revenue / net_profit / debt_ratio / receivable_days / inventory_days
    period: str           # 时间段："2024-Q1"、"2025-06"

    yoy_change: float     # 同比变化率（百分比）

@dataclass
class TrendAnalysis:

```

### 6.5 DispositionAction — 单条处置建议

@dataclass

## 7. LLM调用设计

### 7.1 风险扫描（保留，优化Prompt）

| 项目 | 规格 |
|------|------|
| Prompt | `SYSTEM_RISK_SCAN`（现有，微调） |
| 输入 | 企业材料文本（财务+工商+舆情） |
| 输出 | 结构化JSON：发现的风险点列表，每项含category/level/summary |
| 调用时机 | Step 2，规则引擎之后 |
| 用途 | 补充规则引擎无法覆盖的语义类风险（如"管理层频繁换血暗示内部动荡"） |

### 7.2 趋势分析（改造，激活LLM）

| 项目 | 规格 |
|------|------|
| Prompt | `SYSTEM_TREND_ANALYSIS`（现有未用，需激活并优化） |
| 输入 | 时序财务数据（trend_analyzer.py 提取的结构化数据） + 行业背景 |
| 输出 | 结构化JSON：每个指标的趋势判断 + 整体趋势解读文本 |
| 调用时机 | Step 3，在正则提取+变化率计算之后 |
| 改造要点 | 正则提取+变化率计算保留作为数据预处理；LLM负责趋势解读和异常归因 |

**Prompt改造方向**：
```
你是银行贷后风险分析师。根据以下财务时序数据，分析关键财务指标的变化趋势。

要求：
1. 对每个指标判断趋势方向（上升/下降/平稳）和变化幅度
2. 识别异常变化点并给出可能原因
3. 结合多个指标进行交叉分析（如营收下降+应收增加=回款困难）
4. 给出1-2段总体趋势解读
```

### 7.3 处置建议（改造，接入LLM个性化）

| 项目 | 规格 |
|------|------|
| Prompt | `SYSTEM_DISPOSITION`（现有未用，需激活并重写） |
| 输入 | AlertReport（不含disposition字段） + 企业基本信息 + 授信信息 |
| 输出 | 结构化JSON：DispositionPlan |
| 调用时机 | Step 4，趋势分析之后 |
| 改造要点 | 模板作为Few-shot示例注入Prompt；LLM根据具体风险组合生成个性化建议 |

**Prompt改造方向**：
```
你是银行贷后处置专家。根据以下预警信号和企业情况，生成处置建议。

要求：
1. 每条建议必须包含：紧急程度（紧急/高优/常规）、具体行动、责任方、时限
2. 建议必须与具体风险信号关联，不得空泛
3. 红灯预警至少包含1条"紧急"级别建议
4. 考虑建议之间的优先级排序和逻辑关联
5. 判断是否需要上报上级审批
```

### 7.4 企业名称提取（新增，轻量LLM调用）

| 项目 | 规格 |
|------|------|
| Prompt | 新建，简短system prompt |
| 输入 | 用户输入文本（前200字符） |
| 输出 | 企业全称字符串 |
| 调用时机 | 自定义模式下，用户上传材料后 |
| 策略 | 先尝试正则匹配，失败时调用LLM；预置场景跳过此步 |
