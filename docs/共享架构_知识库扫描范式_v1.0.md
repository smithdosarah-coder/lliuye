## 0. 为什么要做这份共享架构

### 0.1 问题重述

前期 5 个 Demo 在做客户演示时，客户一眼看穿是"假的"：
- 客户输一家企业名，Demo 说"推荐某某渠道"——客户问：**你扫了多少家企业才给出这个？**
- 客户上传一份合规文件，Demo 说"发现 3 处违规"——客户问：**你遍历了哪些业务数据？**
- 客户问一个预警结果，Demo 说"这家企业有风险"——客户问：**你的在贷客户有多少？你都扫过了？**

**症结**：原 PRD 都是"**单查工具**"形态——用户问一次，Agent 答一次。而真实的银行业务诉求是"**扫描目标池，给我一张分级清单**"。

### 0.2 范式升维

| 原形态（v1） | 新形态（v2） |
|---|---|
| 单查：user→agent→answer | 扫描：KB→Scan(targets)→RankedHitList |
| 用户要填空 | 用户上传文件（"锚"） |
| 一次一条结果 | 一张分级命中榜 |
| 无证据链 | 每条命中都有"为什么" |

### 0.3 三个 Agent 的本质同构

| Agent | KnowledgeBase（用户上传的锚）| ScanTargets（扫描目标池）| HitList（分级命中）|
|---|---|---|---|
| **Agent1 获客** | 已有客户名录 + 政策导向 + 行业指引 | 外网企业池（亿级） | Top10 相似新客户线索（含推荐产品+话术） |
| **Agent4 贷中预警** | 预警规则 + 在贷客户名录 + 内部管理制度 | 全量在贷客户 × 外网舆情 + 内部流水 | 红/黄/绿分级风险客户榜 |
| **Agent5 合规巡检** | 监管政策库 + 内部制度 + 业务数据 | 政策条款 × 业务事件笛卡尔积 | 严重/一般/提示分级违规清单 |

三者的差异只在"搜索目标"和"匹配逻辑"，骨架完全一致。因此**必须抽成共享架构**，避免三次重复造轮子。

## 1. 核心范式：KB → Scan → Match → Rank

### 1.1 范式图示

```
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  KnowledgeBase   │    │   ScanTargets    │    │     Matcher      │    │     HitRanker    │
│  （锚：用户上传）  │───▶│   （目标池遍历）  │───▶│  （打分+判级）    │───▶│  （分级命中榜）   │
│                  │    │                  │    │                  │    │                  │
│ • 已有客户名录    │    │ • SearchProvider │    │ • 相似度/规则触发 │    │ • 红黄绿 / Top10  │
│ • 政策/制度       │    │ • 数据库遍历      │    │ • LLM 语义判断    │    │ • 证据链          │
│ • 规则/画像       │    │ • 外网搜索        │    │ • 确定性计算      │    │ • 可导出          │
└──────────────────┘    └──────────────────┘    └──────────────────┘    └──────────────────┘
        ▲
        │ 上传多文件（Excel/Word/PDF）
        │
   ┌──────────┐
   │ 用户（银行）│
   └──────────┘
```

### 1.2 四阶段处理骨架

| 阶段 | 输入 | 输出 | 共享模块 |
|---|---|---|---|
| ① KB 装载 | 多文件（Excel/CSV/Word/PDF） | `KnowledgeBase` 对象（结构化规则+画像+条款） | `KnowledgeBase`, `RuleExtractor` |
| ② 目标扫描 | KB 生成的 query / 规则 | 原始目标池（`list[ScanTarget]`） | `SearchProvider`（Mock/Web 可插拔） |
| ③ 匹配打分 | 目标池 × KB | 带分数的候选 `list[ScoredCandidate]` | `Matcher`（相似度+规则+LLM） |
| ④ 分级输出 | 候选列表 | `HitList`（分级+证据链+可导出） | `HitRanker` |

### 1.3 为什么这样分层

- **① 和 ④ 高度可复用**：三个 Agent 的 KB 装载和分级输出，骨架几乎一致。
- **② 是差异点**：搜索目标不同（企业/客户/政策条款）。但都归为"搜索"，用统一 `SearchProvider` 抽象。
- **③ 是业务逻辑**：每个 Agent 的匹配规则不同，但"打分+判级"的流程可共享。

### 2.2 数据模型（`models.py`）

所有三个 Agent 共用的 Pydantic 模型定义。

```python
# shared/kb_scan/models.py
from __future__ import annotations
from enum import Enum
from typing import Any
from datetime import datetime
from pydantic import BaseModel, Field


# ========== 通用枚举 ==========

class RiskLevel(str, Enum):
    """统一的分级枚举。三个 Agent 都用这套色值和语义。"""
    RED = "red"          # 严重 / 强匹配 / 红灯
    YELLOW = "yellow"    # 一般 / 中匹配 / 黄灯
    GREEN = "green"      # 提示 / 弱匹配 / 绿灯
    INFO = "info"        # 信息性提示，不计入违规/风险统计


class RuleType(str, Enum):
    """规则来源类型。"""
    STRUCTURED = "structured"       # 用户上传的结构化规则（JSON/Excel 直接可用）
    EXTRACTED = "extracted"         # LLM 从 Word/PDF 抽取出的规则
    BUILTIN = "builtin"             # 系统预置规则（如 22 条预警规则）


# ========== KB 层模型 ==========

class RuleItem(BaseModel):
    """从 KB 中抽取出的单条规则（策略/政策条款/预警规则通用）。"""
    rule_id: str = Field(description="规则唯一 ID，如 RULE_001")
    source_doc: str = Field(description="来源文件名，证据溯源用")
    source_page: str = Field(default="", description="页码/章节编号")
    category: str = Field(description="规则类别，如'普惠金融'/'授信集中度'/'反洗钱'")
    title: str = Field(description="规则标题")
    content: str = Field(description="规则原文")
    trigger_condition: str = Field(default="", description="LLM 抽取的触发条件（自然语言）")
    dsl: dict = Field(default_factory=dict, description="可选：结构化 DSL")
    severity: RiskLevel = RiskLevel.YELLOW
    rule_type: RuleType = RuleType.EXTRACTED


class CompanyProfile(BaseModel):
    """企业画像，Agent1/Agent4 共用。"""
    company_id: str = ""
    company_name: str
    unified_credit_code: str = ""
    industry: str = ""
    sub_industry: str = ""
    region: str = ""
    scale: str = ""                          # 大型/中型/小型/微型
    revenue_latest: str = ""
    employee_count: int = 0
    ownership_type: str = ""                 # 国有/民营/外资/混合
    keywords: list[str] = Field(default_factory=list)
    qualifications: list[str] = Field(default_factory=list)   # 资质（高新/专精特新等）
    tags: list[str] = Field(default_factory=list)
    # 拓展字段
    establishment_date: str = ""
    registered_capital: str = ""
    main_business: str = ""
    upstream: list[dict] = Field(default_factory=list)
    downstream: list[dict] = Field(default_factory=list)
    # 风险相关（Agent4 用）
    risk_tags: list[str] = Field(default_factory=list)
    credit_balance: str = ""                 # 在贷余额
    overdue_days: int = 0


class IdealProfile(BaseModel):
    """Agent1 专用：从已有客户名录 + 政策 LLM 抽出的'理想客户画像'。"""
    profile_id: str
    name: str                                 # 画像名，如"制造业 look-alike 画像"
    target_industries: list[str]              # 目标行业
    target_sub_industries: list[str] = Field(default_factory=list)
    target_regions: list[str]
    scale_range: list[str]                    # 规模范围
    revenue_range: tuple[float, float] | None = None  # 营收上下限（万元）
    must_have_tags: list[str] = Field(default_factory=list)   # 必须具备的特征
    nice_to_have_tags: list[str] = Field(default_factory=list)  # 加分项
    exclude_tags: list[str] = Field(default_factory=list)     # 排除项
    policy_context: str = ""                  # 政策扶持方向描述
    reasoning: str = ""                       # LLM 解释："为什么这样定义画像"
    editable: bool = True                     # 前端是否可编辑


# ========== 扫描层模型 ==========

class ScanTarget(BaseModel):
    """扫描目标的抽象载体。三个 Agent 的 targets 都落进这个容器。"""
    target_id: str
    target_type: str                          # "company" | "policy_clause" | "business_event" | "loan_customer"
    payload: dict                             # 原始数据（CompanyProfile / RuleItem / 业务事件 序列化后）


class ScanResult(BaseModel):
    """一次扫描的原始输出（未排序）。"""
    scan_id: str
    scanned_at: str = Field(default_factory=lambda: datetime.now().isoformat())
    provider_name: str                        # "mock" | "web" | "internal_db"
    query_used: str = ""                      # 搜索用的 query（如有）
    targets: list[ScanTarget]
    total_found: int


# ========== 命中层模型 ==========

class Evidence(BaseModel):
    """证据链单元。所有命中都必须有证据。"""
    source: str                               # 来源（"规则:RULE_003" / "搜索:某某天眼查" / "数据库:loan_tbl"）
    snippet: str                              # 证据原文片段
    url: str = ""                             # 可点击链接（如有）


class HitItem(BaseModel):
    """分级命中清单的单条。三 Agent 共用结构。"""
    hit_id: str
    rank: int = 0
    level: RiskLevel
    score: float                              # 0-100
    target: ScanTarget                        # 命中的目标
    matched_rules: list[str] = Field(default_factory=list)   # 命中的 rule_id 列表
    reasons: list[str] = Field(default_factory=list)         # 人类可读的命中理由
    evidences: list[Evidence] = Field(default_factory=list)  # 证据链
    # Agent 定制扩展字段（不 break 共享结构）
    extras: dict = Field(default_factory=dict)


class HitList(BaseModel):
    """最终交付给用户的分级命中榜。"""
    list_id: str
    agent_name: str                           # "channel" | "alert" | "compliance"
    generated_at: str = Field(default_factory=lambda: datetime.now().isoformat())
    kb_summary: str                           # 简述用的 KB（"基于 1200 家在贷客户 + 22 条预警规则"）
    scan_summary: str                         # 简述扫描范围（"遍历全量在贷客户 × 外网舆情近 30 天"）
    total_scanned: int                        # 扫描了多少目标
    total_hit: int                            # 命中多少
    red_count: int = 0
    yellow_count: int = 0
    green_count: int = 0
    hits: list[HitItem]
    # 用于跨 Agent 传递和导出
    exportable: bool = True
```

### 2.3 SearchProvider 接口（`search_provider.py`）

**这是整份架构最关键的抽象**。用户原话：

> "基础框架是搜索，mock 只是填充层。"

所以 SearchProvider 设计必须满足三条硬约束：

1. **MockProvider 实现的方法签名和返回类型，必须和 WebProvider 完全一致**，不能有任何 mock 专属字段。
2. **所有下游模块**（Matcher/HitRanker/Agent）**只接触抽象接口**，不准出现 `if isinstance(provider, MockProvider)` 这类分支判断。
3. **切换只靠一行**：`provider = MockProvider() if settings.DEMO_MODE else WebProvider()`。

```python
# shared/kb_scan/search_provider.py
from __future__ import annotations
from abc import ABC, abstractmethod
from typing import Protocol
from shared.kb_scan.models import ScanTarget, ScanResult, CompanyProfile


class SearchProvider(ABC):
    """
    搜索数据源抽象。三个 Agent 的外网/内网/mock 数据源都走这个接口。

    设计原则：
    - 所有方法必须在 MockProvider 和 WebProvider 中完整实现，方法签名和返回类型一致
    - 不允许 Mock 独有的方法或字段
    - 下游不得感知具体实现
    """

    provider_name: str = "abstract"

    # ---- 通用搜索 ----

    @abstractmethod
    def search_companies(
        self,
        query: str,
        filters: dict | None = None,
        limit: int = 50,
    ) -> list[CompanyProfile]:
        """
        根据 query 和过滤条件，搜索企业池。

        参数:
            query: 自然语言搜索词，如"杭州 精密制造 小微"
            filters: 结构化过滤 {"industry": "...", "region": "...", "scale": [...]}
            limit: 返回数量上限

        返回: CompanyProfile 列表。注意：两种实现必须返回同构对象。
        """
        ...

    @abstractmethod
    def fetch_company_info(self, company_name: str) -> CompanyProfile | None:
        """
        按企业名精确查询公司详情（如天眼查/爱企查接口）。
        Mock 实现从 mock 企业池按名称查找；Web 实现调真实 API。
        """
        ...

    @abstractmethod
    def search_news(
        self,
        query: str,
        days: int = 30,
        limit: int = 10,
    ) -> list[dict]:
        """
        搜索新闻舆情（Agent4 贷中预警用、Agent1 政策窗口用）。

        返回: [{"title": ..., "url": ..., "snippet": ..., "published_at": ...}]
        """
        ...

    @abstractmethod
    def search_policy_clauses(
        self,
        query: str,
        limit: int = 20,
    ) -> list[dict]:
        """
        搜索监管政策条款（Agent5 合规用）。
        Mock 从预置政策库查；Web 从监管网站或搜索引擎查。

        返回: [{"clause_id": ..., "title": ..., "content": ..., "source_doc": ...}]
        """
        ...

    # ---- 内部数据源（生产阶段对接银行核心系统）----

    @abstractmethod
    def iter_loan_customers(
        self,
        filters: dict | None = None,
    ) -> list[CompanyProfile]:
        """
        遍历在贷客户（Agent4 扫描目标池）。
        Mock 实现返回预置 100 家 mock 客户；生产对接贷后管理系统。
        """
        ...

    @abstractmethod
    def iter_business_events(
        self,
        customer_id: str = "",
        event_types: list[str] | None = None,
        days: int = 90,
    ) -> list[dict]:
        """
        遍历业务事件（Agent4/Agent5 用）。
        包含：放款/还款/资金流水/抵质押变动/授信变更等。
        """
        ...

    def __init__(self, mock_data_dir: str = "demo_data/mock_pool"):

        self._companies = self._load_mock_companies()    # 50+ 家预置企业

        self._policies = self._load_mock_policies()
        self._loans = self._load_mock_loans()
        self._events = self._load_mock_events()

    def search_companies(self, query, filters=None, limit=50):
        # 基于关键词 + 过滤器的 mock 打分 + 截断
        results = []
        for c in self._companies:
            if self._match_query(c, query, filters):
                results.append(c)
        return results[:limit]

    def fetch_company_info(self, company_name):
        for c in self._companies:
            if c.company_name == company_name:
                return c
        return None

    def search_news(self, query, days=30, limit=10):
        return [n for n in self._news if self._news_match(n, query, days)][:limit]

    def search_policy_clauses(self, query, limit=20):
        return [p for p in self._policies if query in p.get("content", "")][:limit]

    def iter_loan_customers(self, filters=None):
        if not filters:
            return self._loans
        return [c for c in self._loans if self._match_filter(c, filters)]

    def iter_business_events(self, customer_id="", event_types=None, days=90):
        events = self._events
        if customer_id:
            events = [e for e in events if e.get("customer_id") == customer_id]
        if event_types:
            events = [e for e in events if e.get("type") in event_types]
        return events
```

### 2.4 KnowledgeBase 抽象（`knowledge_base.py`）

```python
# shared/kb_scan/knowledge_base.py
from __future__ import annotations
from pathlib import Path
from shared.kb_scan.models import RuleItem, CompanyProfile, IdealProfile


class KnowledgeBase:
    """
    用户上传多个文件 → 本对象负责把它们解析成结构化规则/画像/条款。
    三个 Agent 的 KB 差异在于"装什么"：
      Agent1: 已有客户名录 + 政策 + 行业指引
      Agent4: 预警规则 + 在贷客户名录 + 管理制度
      Agent5: 政策库 + 内部制度 + 业务数据
    但"怎么装"的流程完全一致。
    """

    def __init__(self, name: str):
        self.name = name
        self.rules: list[RuleItem] = []
        self.companies: list[CompanyProfile] = []          # Agent1/4 的客户名录
        self.ideal_profiles: list[IdealProfile] = []       # Agent1 的理想客户画像
        self.clauses: list[dict] = []                      # Agent5 的政策条款
        self.raw_files: list[dict] = []                    # 原始文件元信息

    # ---- 装载入口 ----

    def load_file(self, file_path: str, doc_type: str = "auto") -> None:
        """
        按文件类型路由到不同解析器。
        doc_type: "rule" | "customer_list" | "policy" | "industry_guide" | "auto"
        """
        path = Path(file_path)
        if doc_type == "auto":
            doc_type = self._infer_type(path)

        self.raw_files.append({"path": str(path), "type": doc_type})

        if doc_type == "customer_list":
            self.companies.extend(self._parse_customer_list(path))
        elif doc_type == "rule":
            self.rules.extend(self._parse_rule_doc(path))
        elif doc_type == "policy":
            self.clauses.extend(self._parse_policy_doc(path))
            # 同时用 RuleExtractor 从政策抽出可执行规则
            from shared.kb_scan.rule_extractor import RuleExtractor
```

### 2.6 Matcher（`matcher.py`）

```python
# shared/kb_scan/matcher.py
from __future__ import annotations
from abc import ABC, abstractmethod
from shared.kb_scan.models import ScanTarget, RuleItem, HitItem, RiskLevel, Evidence


class Matcher(ABC):
    """
    Matcher 是"目标 × KB → 命中项"的核心。三个 Agent 各自继承这个基类实现业务逻辑。

    通用流程：
      1. 对每个 target，评估每条 rule 是否命中
      2. 命中的规则贡献分数和证据
      3. 综合分数后返回 HitItem（未排序，由 HitRanker 排）
    """

    @abstractmethod
    def match_one(self, target: ScanTarget, rules: list[RuleItem]) -> HitItem | None:
        """对单个 target 跑匹配。返回 None 表示完全不命中。"""
        ...

    def match_all(
        self,
        targets: list[ScanTarget],
        rules: list[RuleItem],
    ) -> list[HitItem]:
        hits: list[HitItem] = []
        for t in targets:
            hit = self.match_one(t, rules)
            if hit and hit.score > 0:
                hits.append(hit)
        return hits


# ========== 工具：相似度打分器（Agent1 look-alike 用）==========

class SimilarityScorer:
    """
    基于 CompanyProfile 计算两家企业的相似度。不依赖 LLM，确定性计算。
    Agent1 用它做 look-alike；Agent4 可用于找"与问题客户相似的其他客户"。
    """

    def __init__(self, weights: dict | None = None):
        self.weights = weights or {
            "industry": 0.30,
            "sub_industry": 0.15,
            "region": 0.20,
            "scale": 0.15,
            "tags": 0.20,
        }

    def score(self, anchor_profile, candidate) -> float:
        """0-100 的分数。"""
        s = 0.0
        s += self._industry_sim(anchor_profile, candidate) * self.weights["industry"]
        s += self._region_sim(anchor_profile, candidate) * self.weights["region"]
        s += self._scale_sim(anchor_profile, candidate) * self.weights["scale"]
        s += self._tag_sim(anchor_profile, candidate) * self.weights["tags"]
        return round(s * 100, 1)

    def _region_sim(self, a, c): ...
```

### 2.7 HitRanker（`hit_ranker.py`）

```python
# shared/kb_scan/hit_ranker.py
from __future__ import annotations
from shared.kb_scan.models import HitItem, HitList, RiskLevel


class HitRanker:
    """对命中项打榜、分级、截断。三 Agent 共用。"""

    def __init__(
        self,
        red_threshold: float = 80,
        yellow_threshold: float = 60,
        top_n: int | None = None,
    ):
        self.red_threshold = red_threshold
        self.yellow_threshold = yellow_threshold
        self.top_n = top_n           # None 表示全返回

    def rank(
        self,
        hits: list[HitItem],
        agent_name: str,
        kb_summary: str,
        scan_summary: str,
        total_scanned: int,
    ) -> HitList:
        # 1. 自动判级（若 Matcher 没给 level，则按阈值）
        for h in hits:
            if h.level is None:
                h.level = self._level_by_score(h.score)

        # 2. 按 (level 优先级, score) 排序
        level_order = {RiskLevel.RED: 0, RiskLevel.YELLOW: 1, RiskLevel.GREEN: 2, RiskLevel.INFO: 3}
        hits.sort(key=lambda h: (level_order[h.level], -h.score))

        # 3. 排名
        for i, h in enumerate(hits, 1):
            h.rank = i

        # 4. 截断（Agent1 用 Top10；Agent4/5 一般不截断，返回全部命中）
        if self.top_n:
            hits = hits[: self.top_n]

        # 5. 统计
        red = sum(1 for h in hits if h.level == RiskLevel.RED)
        yellow = sum(1 for h in hits if h.level == RiskLevel.YELLOW)
        green = sum(1 for h in hits if h.level == RiskLevel.GREEN)

        from datetime import datetime
        return HitList(
            list_id=f"HL_{int(datetime.now().timestamp())}",
            agent_name=agent_name,
            kb_summary=kb_summary,
            scan_summary=scan_summary,
            total_scanned=total_scanned,
            total_hit=len(hits),
            red_count=red,
            yellow_count=yellow,
            green_count=green,
            hits=hits,
        )

    def _level_by_score(self, score: float) -> RiskLevel:
        if score >= self.red_threshold:
            return RiskLevel.RED
        if score >= self.yellow_threshold:
            return RiskLevel.YELLOW
        return RiskLevel.GREEN
```

## 3. Mock 层约束（硬性规定）

用户明确强调过："**基础框架是搜索，mock 只是填充层**"。以下是开发必须遵守的硬约束：

### 3.1 接口对称约束

- `MockProvider` 必须实现 `SearchProvider` 中的**全部**抽象方法，不能少一个、也不能多一个。
- 方法签名（参数名、参数类型、默认值、返回类型）必须和 `WebProvider` **一字不差**。
- 返回的 `CompanyProfile` / `ScanTarget` / `dict` 结构必须和 `WebProvider` 返回的同构。
- **禁止** MockProvider 返回 `{"is_mock": True}` 这类 mock 专属字段。

### 3.2 下游无感知约束

下游 Matcher、HitRanker、Agent 业务代码中**禁止出现**以下模式：

```python
# ❌ 错误示例
if isinstance(provider, MockProvider):
    result = provider.get_mock_data()
else:
    result = provider.search_companies(...)

# ❌ 错误示例
if settings.DEMO_MODE:
    ...

# ❌ 错误示例
profile.is_from_mock = True
```

只允许这一种模式：

```python
# ✅ 正确
provider = build_search_provider(demo_mode=settings.DEMO_MODE)
companies = provider.search_companies("杭州 制造业 小微")
```

### 3.3 一行切换约束

整个系统中，mock 和生产的切换**只能发生在一处**：`build_search_provider()` 工厂函数。任何 agent、ui、业务逻辑代码都不允许直接 new `MockProvider` 或 `WebProvider`。

### 3.4 Mock 数据契约

Mock 数据必须模拟"真实调 API 的结果"，不是"理想化的 demo 数据"。具体：

- Mock 企业池 ≥ 50 家（Agent1），覆盖 5 大行业 × 5 大地区
- Mock 在贷客户 ≥ 100 家（Agent4），含正常、逾期、关注等状态
- Mock 政策条款 ≥ 200 条（Agent5），覆盖 10+ 监管文件
- Mock 返回时必须有自然的"不完美"（字段缺失、数据不一致），才像真实 API
- Mock 搜索接口必须支持分页、过滤、空结果等边界

## 4. 三 Agent 共享工作流

### 4.1 输入结构（三 Agent 共用）

```python
class ScanRequest(BaseModel):
    """三个 Agent 接收的统一请求。"""
    kb_files: list[str]                           # 用户上传的文件路径列表
    scan_scope: dict = Field(default_factory=dict)  # 扫描范围约束（地域/行业/时间窗）
    top_n: int | None = None                      # 截断：Top10 / None=全返
    demo_scenario: str = ""                       # 预置场景 ID（如 "S1_manufacturing"）
```

### 4.2 处理骨架（三 Agent 共用）

```python
# 三个 Agent 的 process() 都长这个样子
def process(self, request: ScanRequest) -> Generator[dict, None, HitList]:
    # ① 装载 KB
    yield self._thinking("装载知识库...")
    kb = KnowledgeBase(name=self.agent_name)
    kb.load_files(request.kb_files)
    yield self._message(f"KB 装载完成：{kb.summary()}")

    # ② 构建扫描目标
    yield self._thinking("开始扫描目标池...")
    targets = self._build_scan_targets(kb, request)   # 各 Agent 独立实现
    yield self._progress(step=1, total=3, desc=f"扫描了 {len(targets)} 个目标")

    # ③ 匹配打分
    yield self._thinking("匹配规则与打分...")
    hits = self.matcher.match_all(targets, kb.get_rules())
    yield self._progress(step=2, total=3, desc=f"命中 {len(hits)} 条")

    # ④ 分级打榜
    hit_list = self.ranker.rank(
        hits,
        agent_name=self.agent_name,
        kb_summary=kb.summary(),
        scan_summary=self._describe_scan(targets),
        total_scanned=len(targets),
    )
    yield self._progress(step=3, total=3, desc="打榜完成")

    # ⑤ 返回
    yield self._hit_list(hit_list)
    return hit_list
```

### 4.3 输出格式（三 Agent 共用）

统一输出 `HitList`。前端只需实现"命中榜"这一个组件，三 Agent 都能用。
