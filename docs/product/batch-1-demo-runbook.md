## 1. 演示目标

### 1.1 给谁看

- **主受众**：银行业务部（客户经理/审贷员）+ 科技部（AI 中台对接人）·常见双线到会
- **协同决策方**：合规部（放行关）+ 数据管理部（数据出境审查）+ 采购/法务（L4 阶段才登场）
- **演示级别**：**客户侧 POC pre-check** · 即"能不能上客户真脏数据跑一轮"的门槛展示·尚未到签单演示

### 1.2 想听到什么反馈（成功信号）

| 反馈级别 | 对应话术 | 含义 |
|---|---|---|
| 🟢 强 | "这个证据链做法我们合规那边认" | L2 零幻觉 + 证据溯源打到痛点 |
| 🟢 强 | "能不能下周就拿我们行 N 家真实客户材料试一轮" | 客户主动申请 POC · 把 Phase 1 data-foundation 真脏数据需求打通 |
| 🟡 中 | "比率算得对" + "红线判得准" | §3.1 确定性计算被看见·但没触发 POC 邀约 |
| 🔴 弱 | "整体挺炫的" | 说明陷入视觉叙事·未触达证据/确定性/原因码三层硬货 |

### 1.3 禁区

- 不说"能替代审贷员"——金管总局明文 copilot-only
- 不说"准确率 99%"——除非是 `financial_analyzer` 比率计算的 Python vs 人工一致率（这个可说 ≥99%）
- 不说"已签 XX 行"——即便有客户认可·Batch 1 阶段一律用"客户侧已认"
- 不提 Tavily / DeepSeek / akshare 等供应商具体名字·统一称"外部信号源"

## 2. 15 分钟 6 段 hero moment

**总时长**：15 分钟硬闸 · 留 15-25 分钟 Q&A · 全程一人操作 + 一人解说
**叙事主线**：**贷前获客 → 贷中报告 → 授信决策 → 贷中预警 → 合规自检 → 风控策略** · 按"客户全生命周期"顺序走·不按 Agent 编号走

### 2.1 Agent6 报告助手 · 2 分钟（信贷报告自动生成）

**为什么先讲这个**：Agent6 是矩阵里**唯一达到 L2 证据链成熟度**的 Agent·v16 主管线（classifier → generator → QC gate）已跑通·先把"证据 + 零幻觉"叙事锚牢。

**操作脚本**：
1. 打开 `/today` 或 `/archive/report` workspace（shell v2 canon 路由）
2. 上传中锐网络续贷材料包（21 份异构文件·深柱 data-foundation v2 落地后换真 mock·当前先用 samples/）
3. 跑 `py v16_pipeline.py --source samples/<模板>.docx --material samples`
4. 界面展示：ReportJSON 结构化字段 + 每条数字下挂证据链（原材料文件名 + 段落 ID）+ 占位符未填字段**显式标"未能自动填写"**

**关键展示点（30 秒内必须讲到）**：
- 财务比率不是让 LLM 读 xlsx 算的·是 `financial_analyzer.py` Python 确定性层算完·LLM 只写语义·这就是 §3.1 的硬隔离
- QC Blocker 会拦住占位符残留 / 证据缺失 / 数字与 `financial_analyzer` 不一致三类输出·阻断优先于输出

**硬话术**：
> "你看这个字段没填·我们不编一个·直接标'未能自动填写'·因为对审贷员来讲·一个编出来的准数比一个明确标红的空字段危险 10 倍。"

### 2.2 Agent3 授信决策 · 2 分钟（四维评分 + 红线）

**为什么接着讲**：Agent3 消费 Agent6 的 `EnterpriseProfile` handoff·完成"一键预填"联动·是 L1-11 跨 Agent 联动的硬证据。

**Batch 1 亮点**：code-urgent `28d1037` 修复了 §3.1 反模式——`scoring_model_corporate.py` 原先自己算财务比率·现在**接入 `financial_analyzer.py`**·Agent3/6 数字一致性问题彻底根治。

**操作脚本**：
1. 从 Agent6 报告页一键"送审"·Agent3 自动预填企业画像
2. 触发四维评分：财务 / 行业 / 经营 / 担保
3. 展示雷达图 + 额度建议 + 期限建议 + 红线触发清单
4. 重点展示 Top-5 拒贷原因码（对公 / 对私两套字典·L2-7 合规硬指标）

**关键展示点**：
- 红线触发是规则引擎判的·不是 LLM 猜的（§3.1）
- 每个分数附 reason_codes[]·对标 FCRA AAN / Zest Upstart 可解释性
- 四维评分的"经营" + "行业"这两维走 LLM 概率性·但证据链挂到 `industry_benchmark.py` 行业基准卡 + `material_anchor.py` 材料锚定

**硬话术**：
> "银行最怕的不是 AI 算错·是算错了说不清为啥。每个评分我们附 3-5 个标准原因码·审贷员 30 秒能追到原始证据。"

### 2.3 Agent1 获客 · 3 分钟（信号驱动 look-alike）

**为什么给 3 分钟**：Agent1 是矩阵里唯一走**实搜外部**能力的 Agent·SearchProvider 抽象是 L3-6 双模切换的典型·演示时**必须现场断一次网·让 mock 模式接管**·展示 L1-9/L1-10 降级路径。

**操作脚本**：
1. 打开 `/archive/channel` workspace
2. 上传"历史优质客户名录"知识库（data-foundation v2 落地后是 channel-kb/historical-clients · 当前先用 demo_data/）
3. Agent1 自动抽取客户画像 look-alike 特征·外搜相似行业/区域/规模的新候选企业
4. 展示候选企业清单 + 信号时间线（招投标 / 招聘岗位 / 行业政策 / 舆情）+ 匹配理由 + 推荐产品
5. **中途断网演示**：拔外网·系统切 mock 模式·UI 给"外部信号源暂不可达·已切离线样本"明确提示·不抛技术栈报错

**关键展示点**：
- 每个候选企业至少 2 种信号类型（L3 信号多样性硬指标 · CLAUDE.md §5.2）
- 搜不到实体的"幻觉企业"比例 ≤2%（与 evaluation baseline 对齐）
- SearchProvider 抽象：Mock / Tavily / 企查查实现可切·下游统一消费 `CompanyProfile` · 不依赖数据来源细节

**硬话术**：
> "look-alike 的核心不是推荐·是'为什么推荐'。你看每条候选·都挂了 2+ 种外部信号·信号都带原始 URL·审贷员点进去直接看到原文。"

### 2.4 Agent4 预警 · 2 分钟（批量扫描分级）

**为什么接着讲**：Agent4 是"贷中"的第一个触点·从 Agent3 授信后自然过渡到贷中监控。

**Batch 1 亮点**：code-urgent `28d1037` 新建 Agent4 api.py 端点·前后端终于通了·之前 api.py 缺失是 Q-023 硬洞之一。

**操作脚本**：
1. 打开 `/archive/alert` workspace
2. 加载"在贷客户池"（100 家客户样本 · demo_data/）
3. 触发批量扫描：外部事件（舆情 / 司法 / 招投标异常） + 内部交易（账户行为 / 对手方集中度）双路交叉
4. 展示红 / 黄 / 绿三级仪表盘 + 红灯客户明细 + 处置建议

**关键展示点**：
- 双路交叉命中才升红·单路信号只升黄·降误报
- 红灯客户的**触发证据**必须能打开看原文·这是 L2-6 硬指标
- 扫描是政策事件驱动 / 客户行为事件驱动·不是定期巡检（§4 Agent4 边界）

**硬话术**：
> "100 家客户不是一个个点开查·是一次扫描出红黄绿榜单·审贷员只看红灯的 5-10 家·效率变成原来的 20 倍。"

### 2.5 Agent5 合规 · 2 分钟（政策 vs 制度比对）

**为什么放这里**：Agent5 与 Agent4 共享 `shared/kb_scan/` 扫描底座·但触发源完全不同（政策变 vs 客户变）·演示时**强调边界**·避免客户以为两个 Agent 是重复功能。

**操作脚本**：
1. 打开 `/archive/compli` workspace
2. 上传"2025-10 金管总局助贷新规"作为新政策事件
3. 加载内部业务制度库（银行现行办法 / 流程 / 表单）
4. 触发政策 vs 制度比对·展示违规冲突点清单（条款级溯源）
5. 每条冲突点必须给"为什么冲突 + 怎么改"（L2-9）

**关键展示点**：
- 政策条款解析准确率 ≥95%（L3 Agent5 领域指标）
- 条款引用错误率 ≤1%（引错条款是合规硬红线）
- 违规冲突点召回率 ≥90%（漏检比误报更严重）

**硬话术**：
> "这不是把新政策发给合规官让他自己读·是把新政策每一条都和你们现行制度逐条比一遍·冲突点直接列出来·人工只复核 AI 标的几十条·不用从几百页政策开始读。"

### 2.6 Agent2 风控 · 2 分钟（DSL + KS 回测）

**为什么压轴**：Agent2 是**唯一面向策略经理而非业务人员**的 Agent·话术切换到"策略侧"·且 DSL 可执行率 / KS 计算一致率是 Agent2 独有的领域硬指标。

**Batch 1 亮点**：code-urgent `28d1037` 新建 Agent2 api.py·前后端通了。

**操作脚本**：
1. 打开 `/archive/riskctrl` workspace
2. 输入策略诉求（"降低小微贷通过率 5%·保持 KS ≥ 0.35"）
3. 上传样本 CSV（demo_data/ 脱敏样本）
4. Agent2 生成规则 DSL（JSON 结构） + 触发回测
5. 展示 KS / PSI / 混淆矩阵 + 通过率 / 坏账率对比 + 冠军/挑战者 A/B

**关键展示点**：
- DSL 可执行率 ≥95%（生成的规则直接能跑·不是伪代码 · L3 Agent2 领域指标）
- KS 指标计算与 scikit-learn 一致率 ≥99%（§3.1 确定性计算 · 不让 LLM 算统计量）
- 规则编辑器是 UI 而非 chatbot（L1-2 首屏 3 区块·非纯对话）

**硬话术**：
> "策略经理不是来和 AI 聊天的·是来写规则跑回测的。我们把 DSL 生成 + KS 回测拼在一个界面·生成即跑·跑完对比·不用在 Excel 和 Python 之间来回切。"

## 4. 关键话术（必背 5 段）

### 4.1 证据链话术（任何数字都要说一遍）

> "这个数字不是 AI 猜的·你看后面挂着一个小链·点开是原材料的第 3 页第 2 段·审贷员要质疑随时能追到原文。"

适用场景：Agent6 财务数字 · Agent3 评分依据 · Agent1 外部信号 · Agent4 预警触发 · Agent5 条款引用

### 4.2 确定性数字话术（对抗"AI 会算错"疑虑）

> "比率不是让 AI 读表格算的·是我们 Python 层算完喂给 AI 的·AI 只负责把数字翻译成业务语言·算错的可能性在零点几。"

适用场景：Agent6 / Agent3 财务比率 · Agent2 KS 指标 · 任何数学统计场景

### 4.3 零幻觉话术（对抗"AI 会编"疑虑）

> "填不了的字段·我们直接标红'未能自动填写'·不编。因为对审贷员来讲·一个编出来的准数比一个明确标红的空字段危险 10 倍。"

适用场景：Agent6 占位符残留演示 · Agent1 搜不到实体的候选 · Agent5 条款引用边界

### 4.4 blocker threshold 话术（解释为什么有时不输出）

> "QC 终审会拦住三类不合格输出：占位符残留 / 证据缺失 / 数字与 Python 层不一致。不合格直接阻断·我们宁可不输出也不输出错的。"

适用场景：演示过程中若 QC 触发阻断·正好借机展示 · 或客户问"万一 AI 出错怎么办"

### 4.5 copilot-only 话术（对抗"能不能全自动化"诱问）

> "金管总局 2025 年明文要求 AI 只辅助不替代·我们所有输出都标'建议'不是'决定'·审批人签字栏在 UI 上醒目摆着。等监管放松到允许自动化·高置信字段可以免审·低置信字段保留人工·但那是下一阶段的事。"

适用场景：客户问"能不能让 AI 直接审批" · 合规官质疑责任归属 · 法务问错误担责
