# PRD：客户经理个人助手（AI 中台多 Agent 生态）

**文档版本**：v1.0
**更新日期**：2026-04-07
**文档用途**：内部知识传递（KT），面向产研团队
**阅读对象**：产品经理、算法工程师、后端工程师、部署实施人员

---

## 1. 产品概述

### 1.1 产品定位

客户经理个人助手是一套部署在银行 AI 中台上的多 Agent 生态系统。以对话式交互为入口，整合 6 个专业子 Agent，覆盖客户经理从获客、授信、风控到合规的全业务链条。

**核心理念**：不是 6 个独立工具，而是一个有统一数据底座的智能助手矩阵——Agent 之间数据互通，上游 Agent 的输出自动流入下游 Agent 的输入。

### 1.2 目标用户

- **主要用户**：银行对公客户经理、小微/普惠金融客户经理
- **次要用户**：风控部门、合规部门、管理层（通过 Dashboard 查看数据）

### 1.3 核心价值

| 业务环节 | 当前痛点 | Agent 解决方案 |
|---------|---------|---------------|
| 获客 | 客户经理依赖个人关系网，缺少系统性线索 | 全渠道流量匹配 Agent 自动推荐高意向客户 |
| 授信调查 | 手工撰写报告，耗时且质量参差 | 报告生成助手 Agent 自动生成专业报告 |
| 授信决策 | 审批依赖个人经验，标准不一 | 授信决策辅助 Agent 提供数据化决策建议 |
| 风控策略 | 策略制定周期长，难以快速响应 | 风控策略运营 Agent 辅助策略制定与回测 |
| 贷中监控 | 贷后预警滞后，依赖人工排查 | 贷中风险预警 Agent 实时监控异常信号 |
| 合规检查 | 合规审查人工执行，覆盖率低 | 合规巡检 Agent 自动化合规扫描 |

## 2. 平台架构

### 2.1 AI 中台能力依赖

本产品部署在银行自建或采购的 AI 中台（类 Dify / FastGPT / 自研平台），依赖以下平台能力：

| 平台能力 | 用途 |
|---------|------|
| Multi-Agent 编排 | 主 Agent 调度 6 个子 Agent，子 Agent 以工具形式注册 |
| 知识库管理 | 通用库（行业模板、政策法规）+ 客户私有库（银行内部模板、制度文件）|
| 变量/上下文管理 | Agent 间共享数据（企业画像 JSON、财务锚点等）|
| 对话管理 | 多轮对话、历史记忆、会话隔离 |
| 流式输出 | 长报告生成时的实时反馈 |
| 权限控制 | 不同角色可见不同 Agent 和数据 |

### 2.2 整体架构

**架构分为四层**：

**第一层：用户界面层**
- Dashboard（数据概览 / 指标看板）
- 对话窗口（自然语言交互入口）

**第二层：主 Agent（智能路由 + 编排）**
- 理解用户意图 → 调度对应子 Agent → 聚合结果返回

**第三层：六大子 Agent**

| 编号 | Agent 名称 | 核心职责 |
|------|-----------|---------|
| 1 | 报告生成助手 | 自动生成授信调查报告 |
| 2 | 全渠道流量匹配 | 推荐高意向潜在客户 |
| 3 | 授信决策辅助 | 提供风险评估和额度建议 |
| 4 | 风控策略运营 | 辅助策略制定与回测 |
| 5 | 贷中风险预警 | 持续监控已授信客户异常信号 |
| 6 | 合规巡检 | 自动化合规检查 |

**第四层：共享数据层**
- 企业画像 JSON、财务锚点、风控标签、合规状态
- 知识库（通用 + 私有）、历史报告、预警记录

### 2.3 数据互通设计

Agent 之间不是孤岛，而是通过共享数据层实现上下游联动：

| 步骤 | Agent | 动作 | 产出 |
|------|-------|------|------|
| 1 | 全渠道流量匹配 | 推荐客户企业 | 客户推荐列表 |
| 2 | 报告生成助手 | 生成授信报告 | 企业画像 JSON + 财务锚点 |
| 3 | 授信决策辅助 | 读取报告 + 画像 + 锚点 | 授信建议 + 风险标签 |
| 4 | 风控策略运营 | 读取风险标签 + 行业数据 | 策略建议 |
| 5 | 贷中风险预警 | 读取授信数据 + 企业画像 | 持续监控，输出异常信号 |
| 6 | 合规巡检 | 读取全链路数据 | 合规检查报告 |

**关键数据对象**：

| 数据对象 | 生产者 | 消费者 | 格式 |
|---------|-------|-------|------|
| 企业画像 JSON | 报告生成助手 | 所有 Agent | 结构化 JSON |
| 财务锚点数据 | 报告生成助手 | 授信决策辅助、风控策略运营 | 结构化数值 |
| 授信报告全文 | 报告生成助手 | 授信决策辅助 | .docx / 结构化文本 |
| 风险标签集 | 授信决策辅助 | 风控策略运营、贷中预警 | 枚举标签 |
| 合规状态 | 合规巡检 | 所有 Agent | 通过/未通过 + 明细 |

## 3. 六大子 Agent 详细设计

### 3.1 报告生成助手

> 详细设计见独立文档：PRD_报告生成助手.md

**一句话定位**：上传企业材料 + 报告模板，自动生成可直接提交审批的授信调查报告。

**当前状态**：已完成核心引擎开发（M1-M4），待平台适配（M5）。

**平台注册方式**：作为工具（Tool）注册到主 Agent，暴露以下接口：
- generate_report(template_id, material_files) → 返回报告文件 + 企业画像 JSON + 财务锚点
- check_report_quality(report_file) → 返回 QC 结果

---

### 3.2 全渠道流量匹配 Agent

**定位**：帮助客户经理从多渠道数据中识别高意向、高匹配度的潜在授信客户。

**核心能力**：

| 功能 | 说明 |
|------|------|
| 客户画像匹配 | 基于银行授信偏好（行业、规模、资质），从企业数据库中筛选匹配客户 |
| 多渠道线索整合 | 整合工商数据、税务数据、供应链数据等多维度信息 |
| 意向度评估 | 基于企业经营状态、融资需求信号等评估授信意向 |
| 推荐排序 | 综合匹配度和意向度，输出优先级排序的客户推荐列表 |

**输入**：银行授信政策、行业偏好、区域范围、客户经理历史客户特征

**输出**：
- 推荐客户列表（含匹配理由）
- 客户基础画像（工商信息、行业、规模）
- 建议触达方式

**数据流向**：推荐客户 → 报告生成助手（客户经理选定后，材料进入报告生成流程）

**当前状态**：规划中

---

### 3.3 授信决策辅助 Agent

**定位**：基于授信报告和企业数据，为客户经理和审批人员提供结构化的决策参考。

**核心能力**：

| 功能 | 说明 |
|------|------|
| 报告摘要生成 | 从完整授信报告中提取关键决策要素 |
| 风险评估矩阵 | 从财务、行业、经营、担保四维度量化风险 |
| 授信额度建议 | 基于企业财务数据和行业基准，计算建议授信额度区间 |
| 同业对标分析 | 与同行业已授信客户做关键指标对比 |
| 决策要点提示 | 高亮需要关注的风险点和利好因素 |

**输入**：
- 企业画像 JSON（来自报告生成助手）
- 财务锚点数据（来自报告生成助手）
- 授信报告全文
- 银行内部授信政策

**输出**：
- 风险评估报告（四维度评分）
- 建议授信额度区间及依据
- 关键风险点和缓释措施建议
- 风险标签集（流入风控策略运营 Agent）

**当前状态**：规划中

---

### 3.4 风控策略运营 Agent

**定位**：辅助风控人员制定、评估和优化风控策略，提升策略响应速度。

**核心能力**：

| 功能 | 说明 |
|------|------|
| 策略草案生成 | 基于风险场景描述，自动生成风控策略草案（规则/模型/阈值）|
| 策略回测模拟 | 将策略规则应用到历史数据，评估通过率和坏账率变化 |
| 策略冲突检测 | 检测新策略与现有策略的逻辑冲突或覆盖范围重叠 |
| 行业风险洞察 | 基于行业数据，提供行业风险趋势分析和预警建议 |

**输入**：
- 风险标签集（来自授信决策辅助 Agent）
- 行业数据（知识库）
- 历史授信数据
- 现有风控策略规则集

**输出**：
- 策略建议文档
- 回测报告（通过率、坏账率、影响客户量）
- 策略调整建议

**当前状态**：规划中

---

### 3.5 贷中风险预警 Agent

**定位**：对已授信客户进行持续监控，及时发现异常信号并预警。

**核心能力**：

| 功能 | 说明 |
|------|------|
| 异常信号监测 | 监控企业工商变更、诉讼信息、财务异常等风险信号 |
| 预警等级评估 | 根据信号严重程度和组合情况，评估预警等级（红/黄/绿）|
| 预警推送 | 将预警信息推送给对应客户经理和风控人员 |
| 处置建议 | 基于预警类型提供处置措施建议（约谈、压缩额度、提前收回等）|

**输入**：
- 已授信客户清单 + 企业画像
- 外部数据源（工商变更、司法信息、舆情等）
- 财务数据更新（定期财报）

**输出**：
- 预警信号列表（含触发原因和时间）
- 预警等级和处置建议
- 风险趋势分析（单客户维度和组合维度）

**当前状态**：规划中

---

### 3.6 合规巡检 Agent

**定位**：自动化执行合规检查，确保授信全流程符合监管要求和内部制度。

**核心能力**：

| 功能 | 说明 |
|------|------|
| 授信报告合规检查 | 检查报告内容是否符合监管要求（披露完整性、格式规范性）|
| 流程合规审查 | 检查授信流程是否遵循内部制度（审批权限、材料完整性）|
| 政策法规更新追踪 | 监控监管政策变化，评估对现有业务的影响 |
| 合规报告生成 | 定期生成合规检查汇总报告 |

**输入**：
- 全链路业务数据（报告、决策记录、监控记录）
- 监管政策库（知识库）
- 银行内部制度文件（私有知识库）

**输出**：
- 合规检查结果（通过/未通过 + 具体问题项）
- 整改建议
- 合规状态标签（流入其他 Agent 作为约束条件）

**当前状态**：规划中

## 4. 知识库设计

### 4.1 通用知识库

由平台方维护，所有客户共享：

| 知识库 | 内容 | 更新频率 |
|-------|------|---------|
| 行业模板库 | 各类银行报告模板（普惠、对公、小微等）| 按需更新 |
| 行业知识库 | 行业分类、行业特征、行业风险特点 | 季度更新 |
| 政策法规库 | 银保监会/央行政策文件、监管要求 | 实时追踪 |
| 财务分析基准 | 各行业财务指标基准值（资产负债率、毛利率等）| 年度更新 |

### 4.2 客户私有知识库

由银行客户自行维护：

| 知识库 | 内容 | 说明 |
|-------|------|------|
| 银行自有模板 | 该行定制的报告模板 | 仅对该行客户经理可见 |
| 内部制度文件 | 授信政策、审批流程、合规要求 | 合规巡检 Agent 的核心数据源 |
| 历史报告库 | 已生成的授信报告存档 | 支持相似企业报告参考 |
| 客户白名单/黑名单 | 特定准入或限制名单 | 流量匹配和决策辅助的约束条件 |

## 5. 交互设计

### 5.1 对话入口

用户通过对话窗口与主 Agent 交互，主 Agent 理解意图后路由到对应子 Agent：

| 用户说 | 主 Agent 动作 |
|-------|--------------|
| "帮我生成一份授信报告" | 调用报告生成助手 Agent |
| "看看最近有没有适合授信的客户" | 调用全渠道流量匹配 Agent |
| "这家企业的风险怎么样" | 调用授信决策辅助 Agent |
| "XX公司最近有没有异常" | 调用贷中风险预警 Agent |

### 5.2 Dashboard

展示汇总数据和关键指标：

| 模块 | 展示内容 |
|------|---------|
| 获客概览 | 推荐客户数、转化率、待跟进客户 |
| 报告统计 | 已生成报告数、平均生成时间、QC 通过率 |
| 风险概览 | 在管客户风险分布、预警信号统计 |
| 合规状态 | 合规检查通过率、待整改事项 |

### 5.3 跨 Agent 协作场景示例

**场景：从获客到授信的完整流程**

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| Step 1 | 客户经理说"推荐一些制造业的潜在客户" | 全渠道流量匹配 Agent 返回推荐列表 |
| Step 2 | 客户经理选定某企业，说"帮我生成这家企业的授信报告" | 报告生成助手 Agent 接收材料，生成报告；同时输出企业画像 JSON 和财务锚点到共享数据层 |
| Step 3 | 客户经理说"评估一下这家企业的授信风险" | 授信决策辅助 Agent 读取共享数据层中的画像和锚点，输出风险评估和额度建议 |
| Step 4 | 授信审批通过 | 企业自动进入贷中监控，贷中风险预警 Agent 持续监控 |
| Step 5 | （自动）| 合规巡检 Agent 定期扫描全流程数据，确保授信流程合规 |

## 6. 平台适配要求

### 6.1 平台选型参考

本产品可适配多种 AI 中台平台，核心要求：

| 能力 | 优先级 | 说明 |
|------|-------|------|
| Multi-Agent 编排 | 必须 | 子 Agent 以工具形式注册，主 Agent 按意图路由 |
| 知识库管理 | 必须 | 支持通用库 + 私有库隔离 |
| 变量/上下文共享 | 必须 | Agent 间传递结构化数据 |
| 流式输出 | 必须 | 长报告生成时需实时反馈 |
| 文件上传/下载 | 必须 | 材料上传和报告下载 |
| 权限隔离 | 建议 | 不同银行客户数据隔离 |
| API 网关 | 建议 | 统一接口管理和流量控制 |
| 审批流引擎 | 可选 | 未来对接审批流程 |

### 6.2 部署模式

**推荐：客户本地部署**
- 数据不出银行内网
- 模型可选本地部署或 API 调用（取决于银行安全策略）
- 知识库存储在银行本地

### 6.3 模型配置

| Agent | 推荐模型 | 说明 |
|-------|---------|------|
| 主 Agent（路由）| 轻量模型即可 | 意图识别不需要重模型 |
| 报告生成助手 | DeepSeek-chat / MiniMax-m2.5 | 需要强长文本理解和生成能力 |
| 授信决策辅助 | 同上 | 需要数值推理和分析能力 |
| 其他 Agent | 按需配置 | 可根据任务复杂度选择 |

## 8. 扩展机制

### 8.1 新增 Agent

平台架构支持按需扩展新的子 Agent，步骤如下：

1. 开发 Agent 核心逻辑（Python 服务或平台内编排）
2. 定义输入/输出数据格式
3. 在平台注册为工具（Tool）
4. 在主 Agent 的路由规则中增加新意图
5. 接入共享数据层

### 8.2 数据互通扩展

新 Agent 只需声明自己的数据生产和消费关系，即可自动接入数据流：

| 声明字段 | 说明 | 示例 |
|---------|------|------|
| agent_name | Agent 名称 | "新Agent" |
| produces | 该 Agent 产出的数据类型和格式 | data_type: "xxx_result", format: "json" |
| consumes | 该 Agent 消费的数据，包括来源 Agent | data_type: "company_profile", from: "报告生成助手" |

## 9. 开放问题与风险

| 问题 | 风险级别 | 处理方案 |
|------|---------|---------|
| 各银行 AI 中台能力差异大 | 高 | 核心逻辑与平台解耦，提供适配层 |
| 数据互通的实时性要求 | 中 | 区分实时数据和批量数据，分别处理 |
| 子 Agent 开发优先级 | 中 | 按客户需求和商业价值排序，报告助手先行 |
| 模型本地部署的性能问题 | 中 | 提供云端 API + 本地部署两种方案 |
| 多 Agent 调用成本控制 | 中 | 主 Agent 路由避免不必要的子 Agent 调用 |
| 跨 Agent 数据一致性 | 高 | 共享数据层统一版本管理，避免脏读 |
