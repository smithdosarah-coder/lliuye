## §0. 一眼 Verdict + 适用客户范围

### 0.1 Verdict（销售 / PM 必读 30 秒摘要）

- **L4 当前实际就绪度**：framework ~70% · 数字 / 措辞 / 条款 ~30%（待 6 团队 fill `[TEAM-INPUT-NEEDED]` 占位符 · 详见 §8 input 清单）
- **核心商业化判断**：6 Agent 全 copilot 阶段 · 不替代银行决策（对标金管总局 2025-10 表态"AI 现阶段只能辅助不能替代"）· 报价区间对标金融壹账通 Smart Lender + 拓尔思拓天大模型（2000 万 / 单 · DoD §0 表）
- **短期销售路径**（推荐）：私有部署 fixed by 银行规模（中小行）+ 联合开发（国有大行 / 跨国行）为主战场；SaaS 按席位 / 按调用是补充入口
- **核心 RFP 杀手锏**（对客户痛点）：(1) **境内数据驻留** + (2) **Evidence-First Protocol 零幻觉** + (3) **6 Agent 矩阵跨域协同**（友商通常单 Agent · 我方覆盖贷前 / 贷中 / 贷后全周期）
- **L4 推到 30%+ 路径**：本文档落地 = framework 70% · 6 团队 fill 完 P0 必 fill 项后 = framework 90% + 数字 60% = 总 L4 ~30-40%（实际签合同需走 PoC + 法务 + 财务 闭环 · 非主 CLI 单兵能完成）

### 0.2 适用客户范围 + 推荐 pricing model

| 客户类型 | 典型客户 | 优先 Pricing Model | 数据要求 | 采购周期 |
|---|---|---|---|---|
| 国有大行 | 工 / 建 / 中 / 农 / 交 / 邮 | 联合开发（首选）+ 私有部署（必带） | 客户内网部署 · 0 数据外发 | 6-9 月 RFP cycle |
| 股份行 | 招商 / 浦发 / 平安 / 中信 / 民生 等 | 私有部署 fixed by 中行档 | 客户内网 · 重要数据本地化 | 4-6 月 |
| 城商行 | 北京银行 / 上海银行 / 江苏银行 / 宁波银行 等 | 私有部署 fixed by 小行 / 中行档 | 客户内网 / 混合 | 3-5 月 |

| 互联网银行 | 微众 / 网商 / 新网 / 苏商 等 | SaaS 按 API 调用 | 境内云（云原生客户）| 1-3 月 · 快决策 |

### 0.3 不适用客户（销售勿浪费精力）

- 个人投资者 / 非持牌机构（无放贷资质 = 无信贷场景）
- P2P / 民间借贷平台（监管出清 · 无销售空间）
- 完全无 IT 部门 + 客户经理 < 5 人的小型机构（实施成本 > 年化收益）
- 已采购同类产品 ≥ 3 年且续约率 < 60% 的客户（替换成本高 · 客户对 AI 失望）

## §1. Pricing Model 4 选 1（决策树）

### 1.1 SaaS 按调用次数 (Pay-per-API)

| 维度 | 内容 |
|---|---|
| 典型客户 | 互联网银行 / 中小行 / fintech 创业公司 / PoC 客户 |
| 单价框架 | `[TEAM-INPUT-NEEDED: 销售 - 单次调用单价 X 元 + 月最低消费 Y 万]` |
| 优势 | 低门槛起步 / 客户用多少付多少 / 现金流压力小 / 决策快（IT 部门可自决） |
| 劣势 | 长期 ROI 低于私有部署 / 不适合数据敏感业务（核心数据出本地）/ 突发流量场景需扩容 |
| 适用场景 | 客户先小规模试 PoC · 后续按使用量逐步扩；快速验证 6 Agent 是否解客户痛点 |

**3 档 tier 框架**：
- 入门档（≤ 1 万次/月 · 单价 X 元 · `[TEAM-INPUT-NEEDED: 销售]`）：含基础技术支持（工作日响应）
- 标准档（1-10 万次/月 · 单价 0.6X 元 · `[TEAM-INPUT-NEEDED: 销售]`）：含 24/7 工单支持
- 企业档（≥ 10 万次/月 · 单价 0.4X 元 · `[TEAM-INPUT-NEEDED: 销售]`）：含专属 CSM + 月度业务复盘

**计费颗粒度**：按 6 Agent 各自调用 + token 消耗双计费（详见 `[TEAM-INPUT-NEEDED: PM + 财务 - 计费颗粒度细则]`）

### 1.2 SaaS 按席位 (Per-Seat)

| 维度 | 内容 |
|---|---|
| 典型客户 | 内部团队（如众安自用）/ 中小行（4 角色 ≤ 20 人）/ 信托财富 / 租赁公司 |

| 维度 | 内容 |
|---|---|
| 典型客户 | 国有大行 / 跨国行（与厂商深度绑定 · 长期合作）/ 头部股份行 |
| 报价框架 | `[TEAM-INPUT-NEEDED: 销售 + 法务 - 开发费 + 共拥有 derivative + IP 分成]` |

- 单 Agent 共开（如客户只共开 Agent2 风控 DSL · 客户付开发费 + 共拥有该 Agent 衍生品 · IP 分成 `[法务+财务]`）

- 全矩阵共开（6 Agent 全部 · IP 共享 + 共同对外销售分成 `[法务+财务]`）

### 1.5 决策树（销售用 · 一图选 model）

```
客户规模 + 数据要求 + 合作意愿 → 推荐 Pricing Model

国有大行 / 跨国行 (资产 ≥ 5 万亿) + 数据本地化硬要求 + 长期合作意愿
  → §1.4 联合开发（首选）+ §1.3 私有部署（必带）

国有大行 / 跨国行 + 短期 PoC 试探 (合作意愿弱)
  → §1.3 私有部署 fixed by 大行档（一次性买断起步）

股份行 / 城商行 (资产 5000亿-2万亿) + 数据本地化要求
  → §1.3 私有部署 fixed by 中行档（标准起步）

农商行 / 互联网银行 + 数据可外发 (无强制本地化要求)
  → §1.1 SaaS 按调用 (PoC 启动) → 后续转 §1.2 SaaS 按席位 / §1.3 私有部署小行档

内部团队 / 信托财富 (席位稳定 ≤ 50)
  → §1.2 SaaS 按席位（年付 15% 折）

任何规模 + AI 战略合作意愿强 + 愿意共拥 IP
  → §1.4 联合开发（任何档）
```

### 2.1 3 档 SLA 总表

### 2.2 故障 4 等级定义

- **P1 紧急**：核心功能完全不可用 · 影响 ≥ 50% 用户 · 阻断业务流（如 Agent6 报告生成宕机 · Agent3 决策无法出 · LLM endpoint 全断）
- **P2 高**：核心功能部分受损 · 影响 10-50% 用户 · 业务有 workaround（如 Agent5 政策扫描慢 · Agent1 召回率下降但仍能用）
- **P3 中**：非核心功能 / 偶发 bug · 影响 < 10% 用户（如 UI 显示错位 · Agent4 报警迟延 < 30min）
- **P4 低**：UI 小问题 / 文档错误 / enhancement request

### 2.6 SLA 不可抗力豁免

- 客户违反合同条款（如自行修改部署架构 / 非授权用 LLM endpoint）

## §3. 数据驻留方案

3 种方案 · 客户合规部按需选 · 体现金管总局 + CAC + 数据安全法 + 个人信息保护法 全部硬要求：

### 3.1 境内 only（默认 · 推荐）

| 维度 | 内容 |
|---|---|
| LLM endpoint | DeepSeek（境内 · 上海 / 北京机房 · 备份阿里通义 / 智谱 GLM 切换路径） |
| Search provider | Tavily 国内 endpoint / 企查查 API（全境内） |
| 客户数据 | 完全本地处理 · 不出境 |
| 适用 | 99% 中国境内银行客户 |
| 监管对齐 | 金管总局 + CAC + 数安法 + 个保法 全部满足 |
| DoD 对齐 | L2-15 客户数据本地处理 100% 通过 |
| 实施成本 | 低（默认架构 · 无额外定制）|

### 3.2 客户内网部署（v16 离线模式）

| 维度 | 内容 |
|---|---|
| LLM endpoint | 客户私有 LLM（豆包私有 / 通义私有 / Qwen 自部署 / GPT-4 私有部署 等 · `[TEAM-INPUT-NEEDED: 财务 - 客户私有 LLM 算力费用是否含在我方报价]`）|
| Search provider | 客户内网 KB API（替换 Tavily / 企查查 · 接客户私有数据库）|
| 客户数据 | 物理隔离 · 客户内网零外发 |
| 适用 | 监管极严的国有大行 / 跨国行 / 信托财富 / 涉密机构 |
| 监管对齐 | 等保 2.0 三级 + 信创兼容（鲲鹏 / 麒麟 / 曙光 适配 `[实施 + 安全工程]`）+ 金融云 |
| 实施成本 | 高（含信创适配 + 客户私有 LLM 适配 + 灾备架构 · 6-12 周）|
| 实施周期 | 6-12 周（含 PoC 验证 + 信创栈兼容性测试 + 安全审计配合）|

**SearchProvider 适配机制**（架构层支撑）：
- `shared/sources/` 已实现 BaseSource 协议 + Router + Degrader 三层抽象
- 客户内网 KB API 仅需实现 `shared/sources/impls/<customer_internal>.py` 一个文件
- 不影响其他 5 Agent 业务逻辑 · 切换零成本

### 3.3 混合（敏感本地 · 非敏感走云）

| 维度 | 内容 |
|---|---|
| 敏感字段 | 身份证 / 财务报表 / 授信记录 → 客户内网处理 |
| 非敏感字段 | 行业分析 / 政策解读 / 公开信息搜索 → 境内云 |
| 适用 | 合规要求中等 + 想用云 LLM 算力（DeepSeek 算力 vs 客户私有算力 性价比悬殊）|
| 风险 | 边界划分必须客户合规部签字 · 边界 grey zone 需逐案谈 |
| 监管对齐 | 数安法 / 个保法（前提：分级标签准确 · 重要 / 核心数据本地）|

### 3.4 数据分级标签（DoD L2-14 配套 · 已落 `docs/data-classification.md`）

| 数据级 | 例子 | 处理位置 | 出境策略 |
|---|---|---|---|

#### 异议 1：「价格高 · 比 [对标厂商] 贵 30%」

**异议背景**（5 行）：

**同理回应**：
"完全理解您对成本的关注。AI 投入对银行确实是中长期决策 · 短期 ROI 看不清。我们也希望您选最性价比的方案。先不谈价格 · 让我们看看 6 Agent 矩阵能给您带来的差异化价值。"

**数据反驳**（5 点）：
1. **单 Agent vs 6 Agent 矩阵**：金融壹账通 Smart Lender 客户经理效能 6 倍（仅 Agent6 报告自动化）· 同盾诸葛风险识别 78%→94%（仅 Agent2 风控）。我方一套覆盖：Agent6 报告 + Agent3 决策 + Agent4 预警 + Agent5 合规 + Agent2 风控 + Agent1 获客 = 全周期协同。
2. **数据驻留**：我方境内 only + 客户内网部署 双方案 = 99% 银行 RFP 必需。某些友商境外 LLM = 客户合规部直接 reject。
3. **监管合规**：我方 reason_codes + Evidence-First + 模型卡 全套 = 对齐 CAC AI 治理 2.0 + 人行行标 信息披露指南。友商通常缺 1-2 项 = 客户合规审计风险。
4. **ROI 测算**：单家中型银行 1 年因 Agent6 节省审贷员人时 = `[TEAM-INPUT-NEEDED: 销售 - 测算 case]`。即使我方贵 30% · 1 年 ROI 优于纯 Agent6 友商。
