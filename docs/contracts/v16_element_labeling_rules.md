# V16 元素标注规则文档 v1.0

> 作用范围：V16 信贷报告生成 pipeline 的 `v16_classifier` + 人工 review (`v16_REVIEW_ME_vN.xlsx`)。
> 所有元素(段落 / 表格 cell)必须落入本文档定义的 3 op × 7 label 矩阵,不允许"其他"或"混合"。
> 修改本文档即修改事实契约,须同步 `v16_classifier.py` 的 SYSTEM_PROMPT。

---

## 1. 为什么要标注

一份银行信贷报告模板 = 结构骨架 + 字段占位 + 叙述正文三种文本混合体。LLM 在没有分类的情况下会对三类一视同仁,结果是:
- 骨架被改写成"更通顺"的版本 → 结构瓦解
- 字段占位被 LLM 强行编造 → 幻觉
- 叙述段落被当成字段 → 段落断裂

本标注把每个 element 预先判给一个**确定性 handler**,让 LLM 只碰它该碰的部分。

---

## 2. 3 种 op(操作类型)

| op | 含义 | 执行主体 | 禁止 |
|---|---|---|---|
| **PRESERVE** | 逐字保留,不改 | 代码 | LLM 接触 |
| **FILL** | 用客户数据替换值;无数据留空 + pending | 代码(查表) | LLM 编造 |
| **REWRITE** | 基于客户材料整段重写 | LLM(evidence-first 3 阶段) | 正则兜底 |

判别 op 时先问一个问题:**这段文字是结构 / 字段 / 叙述中的哪一类?**

---

## 3. 7 个 label(细分标签)

每个 label 绑定一个 op,下游 handler 按 `(op, label)` 二元组路由,禁止在 handler 内跳转。

### 3.1 `SCAFFOLD` — 骨架保留 (op=PRESERVE)

**定义**:报告的章节骨架、字段标签、表头、编号,删一字结构就塌。

**识别线索**(满足任一即可):
- 段落 style 是 `Heading 1/2/3` 或 `标题 1/2/3`
- 独立行是章节编号 `一、/（一）/1./①/i./甲、`
- 表格 header 行的多个短标题(`序号 / 授信条件 / 具体落实情况`)
- 纯字段标签(不含取值):`客户名称：`、`注册资本：`、`申报方案：`
- 表格单位说明:`单位:万元、%`
- 纯列标题:`合计 / 序号 / 其中 / 其他`

**正例**
```
一、授信客户基本情况
（二）经营分析
法定代表人：
序号 | 授信条件 | 具体落实情况
```

**反例**(不是 SCAFFOLD)
```
法定代表人：张XX，福建人   ← 含值 → FILL
公司主要从事智慧水利系统集成    ← 叙述 → REWRITE
```

---

### 3.2 `PRESERVE` — 指引保留 (op=PRESERVE)

**定义**:银行侧规范话术、合规声明、操作指引,客户数据无关,改动会触发合规问题。

**识别线索**:
- 开头含 `如涉及 / 如未落实 / 请说明 / 可附图`
- 开头含 `注: / 备注: / 说明:`
- 合规声明类:`该部分数据从"风险监测系统"直接取数`
- 通用核实类:`已核实主要银行账户流水中付款对象与提供的上游订单中的企业名称一致`

**正例**
```
注：若企业反馈"无"，建议出具书面声明并加盖公章
用电量核实（中小型制造业企业适用，汇总其主要经营实体数据填列）：
该部分数据从"风险监测系统"直接取数，系统上线前由经营单位填列。
```

**反例**
```
客户机构设置为：综合管理部、计划财务部...   ← 含客户方示例值 → CLEAR
```

---

### 3.3 `FILL` — 字段填值 (op=FILL/label=FILL)

**定义**:客户方字段,且本报告有对应的结构化数据源(KB / 财务表)可查。

**识别线索**:
- 字段属于"**客户方**"(见第 5 节主体辨析)
- 值是具体数字、日期、专有名词、短语
- 代码可通过 `kb.facts[key]` 或 `financial.period_value()` 查到

**客户方字段白名单**(常见):
- 客户名称 / 注册资本 / 实收资本 / 成立时间
- 法定代表人 / 实际控制人 / 股东名称 / 持股比例
- 所属行业 / 主营业务 / 经营地址 / 邮编 / 电话
- 审计会计师事务所 / 财报年度
- 营收 / 净利润 / 总资产 / 负债率(取自客户财报)
- 各科目取值(货币资金、应收账款、存货...)

**正例**
```
人民币 195,000 万元          ← 表格 cell 填 registered_capital
法定代表人：张XX，中国国籍    ← 填 controller
客户名称：                   ← 空冒号字段,值去 kb 查 company_name
100.00%                      ← 持股比例
```

**反例**
```
PD评级：4                    ← 银行方 → CLEAR
其它指标：基本户，代发工资     ← 指引性表头(客户方字段但值不是客户给) → PRESERVE 或 SLOT
实际主营业务：主营芯片设计...  ← 含示例值不是客户值 → CLEAR 或 REWRITE
```

---

### 3.4 `CLEAR` — 清空 + pending (op=FILL/label=CLEAR)

**定义**:字段有"示例值"残留在模板里,但**当前客户没有对应数据**或该字段是**银行方主体**,必须清空值并挂 `【待客户经理填写】` pending tag。

**识别线索**:
- 字段主体是银行/支行/客户经理(见第 5 节)
- 字段是模板示例(含具体公司名 / 数字但非当前客户)
- 字段含 `XXX / XX / X万元` 等占位残留
- 字段属于"银行侧评级"类(PD 评级 / 内部评级 / 白名单 / 我行投向)

**正例**
```
PD评级：4                                    申报单位：大客户一部
我行投向政策对应行业：商业服务业
公司机构设置为：综合管理部、计划财务部、信息科技部...   （非本客户机构）
上年度末社保人数     人；注册资本：         万元
```

**反例**
```
□专精特新中小企业            ← 含 □ → CHECKBOX
法定代表人:                  ← 空值等待填写 → FILL(不是 CLEAR,KB 有值)
```

---

### 3.5 `SLOT` — 多槽拆分 (op=FILL/label=SLOT)

**定义**:一个 element 里含 ≥2 个并列字段占位(通常冒号 ≥2),需要拆成子槽分别 KB 查找。

**识别线索**:
- 一行里有多个 `字段名：值` 结构(值可以为空)
- 含 `、 / ;` 连接的多字段陈述式
- 代码上需要 regex 切分后逐槽填充

**正例**
```
上年度末社保人数     人；注册资本：         万元、实收资本：        万元；法定代表人：       。
规模划型：□微型 □小型 □中型，所属客群：□支持类 □审慎类 □禁止类
经营地址：XX路XX号，面积XX平，占地面积7408㎡，建筑面积1203
```
(注:如同时含 `□`,整行判 CHECKBOX 优先级更高)

**反例**
```
注册资本：4100万元            ← 单槽 → FILL
公司主营智慧水利、智慧教育     ← 叙述非字段枚举 → REWRITE
```

---

### 3.6 `CHECKBOX` — 复选框勾选 (op=FILL/label=CHECKBOX)

**定义**:含 `□ / ☐ / ☑ / ■` 等复选框字符,执行逻辑是勾选符合客户的,其余保留或打叉,**不是清空、不是填值**。

**识别线索**:
- 文本中含任一 `□ / ☐ / ☑ / ☒` 字符(哪怕只有 1 个)
- 形式是 `□选项A;□选项B` 或 `□是 □否`
- 代码逻辑:根据 `kb.facts` 判定是/否,替换对应 `□` 为 `☑`

**正例**
```
□专精特新中小企业；□专精特新"小巨人"企业；
授信方案：□新客户 □存量客户
□排污许可证（编号：XXX，有效期至 年 月 日）
```

**反例**
```
专精特新"小巨人"企业          ← 无 □ → SCAFFOLD 或 FILL
```

**优先级**:只要含 `□`,无论其他特征如何都判 CHECKBOX(比 SLOT / CLEAR 都高)。

---

### 3.7 `REWRITE` — 整段重写 (op=REWRITE)

**定义**:叙述性正文、分析段、评价段、趋势描述、业务论述,LLM 基于 evidence-first 三阶段重写。

**识别线索**:
- 长度 ≥ 50 字
- 含自然语言叙述特征(主谓宾完整句)
- 含具体示例数字但**在叙述语境下**(不是字段取值)
- 财务分析段:`截至...公司...较年初增加...主要由于...`
- 行业分析段 / 风险评价段 / 授信结论段

**正例**
```
企业成立于2010年5月，经营地址位于福州市仓山区XX工业园区...面积7408㎡...
货币资金：截至2022年9月，公司货币资金为5409万元，较2021年底增加了约1978万元。随着近年企业的高速发展...
公司目前人才结构较为合理，拥有一支实力雄厚的专家队伍，其中教授级高级工程师...
```

**反例**
```
主要偿债指标表       单位：万元、%    ← 表头 → SCAFFOLD
公司机构设置为：综合管理部、计划财务部    ← 示例枚举非客户值 → CLEAR
```

**REWRITE 的硬约束**:
- 同 section 内所有 REWRITE 元素**一次 LLM 调用**合批生成(避免跨段叙事断裂)
- 批次上限 12 个 element / call(防 JSON 截断)
- 财务段落必须含 ≥4 处"数字紧跟同比/较年初"的连写(QC scorer 约束)
- BS 科目用"较年初",IS/CF 科目用"同比"(口径严明,不可混)
- 归因句 ≥2 处("主要由于 / 归因于")
- 异常项原文引用"大幅 / 突增 / 骤降 / 积压"等定性词

## 4. op × label 路由矩阵(唯一真源)

| op | label | Handler 函数 | 说明 |
|---|---|---|---|
| PRESERVE | SCAFFOLD | `keep_as_is` + `body_gap_inject` | 结构骨架原样保留;若同 section 后续无 body,注入 `【待根据客户材料补充】` |
| PRESERVE | PRESERVE | `keep_as_is` | 指引文字 / 合规话术,原样保留 |
| FILL | FILL | `kb_lookup_fill` | KB / 财务指标查表,命中填,不命中 `【未能自动填写】` |
| FILL | SLOT | `multi_slot_decompose` | 拆子槽,每个独立 lookup |
| FILL | CLEAR | `clear_with_pending_marker` | 清空 + `【待客户经理填写】`高亮标签 |
| FILL | CHECKBOX | `checkbox_tick` | 按 KB 判是/否,勾/叉相应符号 |
| REWRITE | REWRITE | `section_batch_rewrite` | 同 section 合批 LLM 生成(evidence→grounded→audit) |

**其他组合一律非法**(例:`PRESERVE/FILL`、`REWRITE/SCAFFOLD`)。

## 5. 银行方 vs 客户方字段辨析(关键)

最容易标错的场景:字段名看起来像客户信息,但主体是银行。LLM 会用客户档案强填,是**重点幻觉来源**。

### 5.1 银行方字段(主体 = 银行,一律 CLEAR)

| 字段类别 | 常见字段名 |
|---|---|
| 申报主体 | 申报单位 / 申报行 / 申报支行 / 经办行 |
| 客户经理信息 | 客户经理 / 联系电话(客户经理的) / 所属部门 |
| 审批流程 | 授信审批岗 / 评议人 / 评议会 / 审批岗 |
| 历史授信 | 上一期授信敞口 / 上期批复意见 |
| 银行评级 | PD 评级 / 内部评级 / 白名单类型 / 我行投向政策 |

**识别线索词**:`我行 / 本行 / 支行 / 分行 / 客户经理 / 申报 / 评议 / 授信审批 / 批复`

**关键原则**:即便 LLM 可以从客户档案"拼"出像样的值,也必须 CLEAR。例:把客户注册地当成"申报单位"是高频错误。

### 5.2 客户方字段(主体 = 客户,正常 FILL)

| 字段类别 | 常见字段名 |
|---|---|
| 基本信息 | 客户名称 / 统一社会信用代码 / 注册资本 / 实收资本 / 成立时间 |
| 人员 | 法定代表人 / 实际控制人 / 股东 / 持股比例 / 员工人数 |
| 业务 | 所属行业 / 主营业务 / 经营地址 / 经营面积 / 自有还是租用 |
| 联系方式 | 邮编 / 电话(企业的) / 基本户 |
| 审计 | 会计师事务所 / 审计年度 |
| 财务 | 营收 / 净利润 / 总资产 / 负债率 / 各会计科目值 |

## 6. 判别规则(按优先级从高到低)

标注时**按顺序**应用,第一个命中的规则决定 label,不继续往下走。

1. **含 `□ / ☐ / ☑ / ☒`** → CHECKBOX
2. **段落 style 是 Heading/标题 N** → SCAFFOLD
3. **独立行是章节编号 `一、/（一）/1./①`** → SCAFFOLD
4. **表格 header 行多个短标题** → SCAFFOLD
5. **纯字段标签(冒号结尾无值)** → SCAFFOLD (下游 handler 会去 KB 查取值;若值空则转 FILL 逻辑)
6. **银行方字段命中(第 5.1 节词表)** → CLEAR(**无视是否含客户档案可用值**)
7. **一行含 ≥2 个并列 `字段:值` 结构** → SLOT
8. **含纯占位符**(≥4 连续下划线 / `XX年XX月` / `____`) → SLOT
9. **含具体数字+单位** 且字段属客户方 且 KB 可查 → FILL
10. **含具体数字但是示例残留**(不是当前客户值) → CLEAR
11. **长度 ≥ 50 字 + 自然语言叙述** → REWRITE
12. **开头 `如涉及/注:/备注:/说明:/请说明/可附图`** → PRESERVE
13. **默认兜底** → REWRITE(若长)、SCAFFOLD(若短)

## 7. 边界情况与争议处理

### 7.1 字段标签 + 示例值同段

例:`注册资本：1000万元(示例)`

处理:整段判 FILL(label=FILL),下游 handler 用 KB 值替换,包含"(示例)"尾巴一并清掉。

### 7.2 多占位 + □ 混合

例:`规模划型：□微型 □小型 □中型，所属客群：□支持类 □审慎类 □禁止类`

处理:含 `□` 优先级高于 SLOT,判 CHECKBOX。下游 checkbox_tick 内部自己处理多字段多选项。

### 7.3 表头文字看起来像指引

例:`用电量核实（中小型制造业企业适用，汇总其主要经营实体数据填列）：`

处理:判 PRESERVE(指引),不是 SCAFFOLD。两者都是 op=PRESERVE,下游都走 `keep_as_is`,但 label 的语义区分给未来扩展留门。

### 7.4 合并单元格重复文字

例:多个相邻 cell 都是 `用电量核实...`

处理:每个 cell 独立标注,统一判 PRESERVE。下游 apply_to_docx 按 location 定位,不去重。

### 7.5 confidence < 0.6 的兜底

classifier 给出 confidence < 0.6 的项必须人工 review,不接受 LLM 自洽结果。在 `v16_REVIEW_ME_vN.xlsx` 中标 `⚠`,review 时重点检查。

### 7.6 坏样本

若 element 根本不应被抽进来(空字符串、纯空白、样式表残留),标 `SKIP`,下游 skip_list 里过滤,不分配 handler。

## 8. 标注流程 SOP

### 8.1 机器分类(v16_classifier.py)

1. 读取 `outputs/v16_labeled_elements.json`(已抽样 192 个 element)
2. 对每个 source docx 全量抽取 + 建 section 索引(nearest preceding heading × 3 层)
3. 按 source × section 分组,batch=15 送 LLM
4. LLM 按本规则输出 `{location, op, label, confidence, justification}`
5. 保存到 `outputs/v16_llm_classified.json`

### 8.2 人工 review(v16_REVIEW_ME_vN.xlsx)

1. 打开最新版 xlsx,按 label 分 sheet
2. **重点扫** `confidence < 0.7`(标 ⚠)的行
3. 标对 → 跳过;标错 → 行末写 `→ 应该是 {正确标签}` + 原因
4. 坏样本 → 标 `SKIP`
5. 回填到 classifier SYSTEM_PROMPT 作为 few-shot(若系统性错误)或直接修 label(若个案)

### 8.3 争议升级

- 两人 review 不一致 → 以银行方 vs 客户方辨析(第 5 节)为准
- 规则未覆盖的新情况 → 先标 `AMBIGUOUS` + 备注,积累后更新本文档

## 9. 常见错误与纠正(V4 review 累计 16 处)

| 错误 | 纠正 |
|---|---|
| 把 `法定代表人：张XX，中国国籍...` 标 REWRITE | 这是多槽字段 → FILL 或 SLOT;整段 LLM 重写会编身份信息 |
| 把 `PD评级：4` 标 FILL(以为可以查 KB) | PD 评级是银行方字段 → CLEAR,客户档案没有 PD |
| 把 `□专精特新中小企业` 标 SLOT | 含 `□` 第一规则 → CHECKBOX |
| 把 `主要偿债指标表  单位：万元、%` 标 REWRITE | 是表格标题/单位说明 → SCAFFOLD |
| 把 `合并损益表主要数据如下：单位：万元、%` 标 SCAFFOLD | 是字段 + 示例残留 → CLEAR(因下游会被示例表格残影污染) |
| 把 `该部分数据从"风险监测系统"直接取数` 标 SCAFFOLD | 是合规说明 → PRESERVE(都是 op=PRESERVE 但语义不同) |
| 把空的 `授信客户风险信息：` 标 FILL | 是章节标签 → SCAFFOLD;其 body 由后续 REWRITE 元素产生 |

## 10. 与下游 handler 的契约

- 路由表硬编码在 `v16_op_handlers.py` 顶部 `OP_LABEL_HANDLERS: dict[(op, label), Callable]`
- Handler 内部**禁止**分支跳转到其他 handler(例:FILL handler 遇到含 `□` 的元素不能调 CHECKBOX handler,而是返回 `Error: misclassified, please relabel`)
- 修改本规则 → 修改 classifier prompt → 跑 classifier → review xlsx → 修改 handler 路由表,顺序不可倒
