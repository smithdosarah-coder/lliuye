**版本**：v1.0
**日期**：2026-04-13
**作者**：众安信科AI中台团队
**文档性质**：内部交付改造方案
**所属平台**：众安信科 · 乾策平台（X-Nexus）

---

## 1. 执行摘要

### 为什么改

众安信科AI中台（乾策平台/X-Nexus）已完成5个信贷Demo智能体的后端业务逻辑开发（约200KB代码），覆盖获客、风控、授信、预警、合规全链条。但当前所有Demo的前端均为Gradio默认chatbot模板，5个Agent页面在视觉上完全一致，无品牌感，无预置演示数据，无法直接用于客户演示。

### 改什么

- **扔掉**：所有前端app.py（通用chatbot模板）、空壳portal_app.py
- **保留**：全部后端业务逻辑（agent.py、规则引擎、评分模型、分析流水线、Pydantic数据模型、提示词、共享基类）
- **新建**：统一Portal入口、5套差异化前端UI、预置Mock数据体系、报告导出功能、跨Agent数据流

### 怎么改

分4个阶段推进：PRD与方案输出（P3）、Demo改造（P4）、平台适配（P5）、客户交付（P6），共计约5周。

### 预期效果

- 客户坐在会议室，销售点3下鼠标即可展示完整场景
- 5个Demo各具视觉特色，品牌统一，体验一致
- 预置场景一键启动，30秒内看到完整结果
- 支持从获客到合规的全链路联动演示（约20分钟）

|-------|-----------|-----------|-----------|---------|

### 2.2 共性问题清单

| 序号 | 问题 | 影响 |
|------|------|------|
| 1 | 前端5个页面UI完全相同（Gradio默认chatbot） | 无法体现各Agent差异化价值 |

| 6 | 无报告导出功能 | 演示结果无法留存给客户 |
| 7 | Agent3定位偏差 | 当前是报告生成包装，应为风险评估+额度建议 |

## 3. 改造目标

### 3.1 可演示产品判定标准

| 维度 | 判定标准 |
|------|---------|
| 零配置启动 | 不需要填API Key、不需要上传文件、不需要解释技术概念 |
| 视觉差异化 | 5个Demo各有独立布局和视觉元素，不是"同一个chatbot换了标题" |
| 一键演示 | 每个Agent内置2-3个预置场景，点击即可启动完整流程 |
| 时效要求 | 预置场景30秒内出完整结果 |
| 品牌统一 | 统一Portal入口，众安信科品牌色，专业视觉 |
| 结果可导出 | 每个Agent支持报告/结果文件下载 |
| 链路联动 | 支持从获客到合规的全链路20分钟演示 |

### 3.2 量化验收指标

| 指标 | 目标值 |
|------|--------|
| 单Agent演示时长 | 3-8分钟 |
| 全链路联动演示时长 | 约20分钟 |
| 预置场景响应时间 | < 30秒 |
| Portal Tab切换延迟 | < 1秒 |
| LLM调用次数/场景 | 不超过3次 |

## 4. 改造策略

### 4.1 保留/扔掉/新建矩阵

| 层级 | 保留 | 扔掉 | 新建 |
|------|------|------|------|
| 业务逻辑 | 5个agent目录下的agent.py、规则引擎、评分模型、分析流水线 | -- | -- |
| 数据模型 | Pydantic模型（RuleSet / AlertSignal / PolicyDocument等） | -- | -- |
| 提示词 | prompts.py（3-4套/Agent） | -- | 按Demo场景微调 |
| 共享基类 | base_agent.py（事件协议+LLM封装） | -- | -- |
| 企业画像 | enterprise_profile.py | -- | 接通数据流 |
| 前端 | -- | 全部app.py | 每个Agent独立定制UI |
| 统一入口 | -- | portal_app.py（空壳） | 全新Portal + 导航 |
| Demo数据 | -- | -- | 每个Agent 2-3套预置场景 |
| 导出功能 | -- | -- | 每个Agent支持报告下载 |

### 4.2 改造原则

1. **后端不动，前端重做**：后端代码已验证可运行，不做结构性改动，仅做接入层适配
2. **Mock数据驱动**：Demo阶段所有数据预置，不依赖外部接口
3. **渐进式交付**：先Portal+1个Agent跑通全流程，再铺开其余4个
4. **LLM输出可缓存**：预置场景的LLM响应首次调用后缓存，后续演示秒出

## 5. Portal统一入口设计

### 5.1 架构设计

一个Gradio应用作为统一入口，通过Tab页切换5个Agent模块。

```
+------------------------------------------------------------+
|  众安信科 · 信贷AI智能体矩阵                    [Settings]  |
+------------------------------------------------------------+
|  [获客匹配] [风控策略] [授信决策] [贷中预警] [合规巡检]       |
+------------------------------------------------------------+
|                                                             |
|    各Agent差异化内容区                                       |
|    (布局、组件各不相同)                                       |
|                                                             |
+------------------------------------------------------------+
```

### 5.2 品牌规范

| 要素 | 规格 |
|------|------|
| 主色 | 众安蓝 #1677FF |
| 字体 | 思源黑体 / PingFang SC |
| Header高度 | 56px，含品牌Logo + 产品名 + Settings入口 |
| Tab导航 | 5个Tab等宽排列，选中态底部蓝色指示线 |

- 支持DeepSeek / Kimi / MiniMax / OpenAI / Anthropic多模型切换
- 配置持久化到本地JSON文件，重启不丢失

## 6. 各Agent改造概要

### 6.1 全渠道流量匹配智能体（Agent #1）

**定位**：银行信贷获客环节AI辅助工具，从5大类13个子渠道中智能匹配最优获客路径。

**核心改造点**：
- 新建表单+卡片流双栏布局（左：企业输入表单 / 右：渠道推荐卡片瀑布流）
- 新建20家mock企业预置数据库，用户选择即可启动匹配
- 渠道规则从硬编码改为可配置JSON
- 新增匹配结果导出PDF功能
- 接入联网搜索增强，捕捉实时政策与行业趋势

**前端差异化**：匹配得分进度条、渠道类型色块标签、搜索进度实时展示

**预置场景**：杭州精密制造企业获客、深圳科技企业获客

**验收标准**：
- 预置场景一键启动，20秒内展示TOP5渠道推荐
- 每个推荐含5维评分（行业/规模/地域/政策/历史）+ 营销建议
- 推荐结果可导出PDF

---

### 6.2 风控策略运营助手（Agent #2）

**定位**：支持自然语言配策略、自动回测评估、差错案件诊断的风控全生命周期管理工具。

**核心改造点**：
- 新建规则编辑器+图表双区布局（上：对话输入+DSL展示 / 下：数据图表区）
- 接通metrics.py（KS/PSI/混淆矩阵/F1），回测报告含可视化图表
- 接通compare_strategies()，支持新旧策略对比视图
- 预置3套回测场景（含CSV数据+规则集）
- 新增回测报告导出PDF

**前端差异化**：规则DSL代码块高亮、通过率/拒绝率圆环图、KS曲线折线图、混淆矩阵热力图

**预置场景**：小微信用贷策略回测、差错案件诊断、自然语言配策略

**验收标准**：
- 3分钟内完成"策略描述 -> 规则生成 -> 回测评估 -> 报告输出"完整闭环
- 自然语言输入可正确转化为RuleCondition DSL
- 新旧策略对比图表清晰直观

---

### 6.3 授信决策辅助智能体（Agent #3）

**定位**：读取企业画像（EnterpriseProfile）和财务锚点数据，输出四维风险评分 + 授信额度建议区间 + 同业对标分析 + 结构化审批意见书。

**核心改造点**（此Agent需重写后端）：
- 重新定位：从"报告生成包装"变为"读报告 -> 出风险评估+额度建议"
- 新建四维风险评估矩阵（财务风险/行业风险/经营风险/担保风险），确定性算法计算
- 新建额度建议算法（营收法/净资产法/现金流法/担保法四种测算取交集）
- 新建同业对标模块（10家mock同业数据）
- 新建三栏布局（左：材料清单 / 中：对话 / 右：报告预览）

**前端差异化**：四维风险雷达图、额度建议条形图、同业对标表格

**预置场景**：瑞恒精密制造有限公司首次授信评估（含完整EnterpriseProfile JSON）

**验收标准**：
- 端到端评估耗时 < 30秒
- 4个维度均有0-100评分 + 文字解读
- 给出建议额度区间（下限-上限）+ 推荐值 + 计算依据
- LLM调用不超过2次

---

### 6.4 贷中风险预警助手（Agent #4）

**定位**：基于规则引擎（22条规则、6大类别）+LLM双通道的存量信贷客户实时风险预警与智能处置系统。

**核心改造点**：
- 保留并增强信号灯UI（红黄绿灯脉冲动画，唯一有差异化的前端元素）
- 预警规则从11条扩展到22条，类别从5个扩展到6个
- 趋势分析从纯正则改为LLM辅助分析
- 处置建议从19个预设模板改为LLM个性化生成 + 模板fallback
- 新建仪表盘+时间线布局（顶：信号灯仪表盘 / 下：预警时间线+处置卡片）

**前端差异化**：红黄绿信号灯脉冲动画、预警事件时间线、处置建议卡片

**预置场景**：华联精密制造红灯预警（7个风险信号叠加）、盛达国际贸易黄灯预警（4个关注信号）

**验收标准**：
- 信号灯颜色与预警结果严格对应
- 预置场景全自动运行，无需手动输入
- 处置建议具体到时间节点和行动项
- 预警报告PDF一键导出

---

### 6.5 合规巡检智能体（Agent #5）

**定位**：银行信贷业务全流程合规自动审查工具，输入政策文件+业务记录，输出逐条合规检查报告和分阶段整改计划。

**核心改造点**：
- 文件分类从关键词猜测改为LLM分类
- 政策文本处理从截断（12000字）改为摘要（支持30000字+）
- 缺陷分级引入LLM辅助（替代纯关键词匹配）
- 新建政策树+检查清单双栏布局（左：政策条款树 / 右：合规检查清单+整改计划）
- 新增合规检查报告Word格式导出

**前端差异化**：合规率仪表盘、通过/未通过/部分通过三色标签、政策条款树状导航

**预置场景**：《商业银行互联网贷款管理暂行办法》合规检查（56条政策、5处埋入违规）

**验收标准**：
- 预置场景 < 60秒完成全量检查
- 政策全部条款均有对应检查结果
- mock数据中埋入的5处不合规项全部检出
- 一键导出结构化Word报告

### 7.3 跨Agent数据流

EnterpriseProfile JSON作为Agent间数据传递的标准载体：

1. **报告生成助手**完成尽调后 -> 产出EnterpriseProfile JSON -> 存入共享上下文
2. 用户切换到其他Agent Tab时 -> 系统自动检测已生成的企业画像 -> 提示"检测到XX企业画像，是否加载？"
3. Demo阶段用预置的企业画像JSON模拟此流程，不依赖实时生成

**关键数据对象流转**：

| 数据对象 | 生产者 | 消费者 | 格式 |
|---------|--------|--------|------|
| EnterpriseProfile JSON | 报告生成助手 | 所有Agent | Pydantic模型，40+字段 |
| 财务锚点 | 报告生成助手 | 授信决策辅助、风控策略运营 | 结构化数值 |
| 风险标签集 | 授信决策辅助 | 风控策略运营、贷中预警 | 枚举标签列表 |
| 合规状态 | 合规巡检 | 所有Agent | 通过/未通过 + 明细 |

### 7.4 Mock数据设计原则

- 参考真实银行数据格式和分布，字段命名对齐银行术语
- 每个场景包含完整的输入/输出参考，便于验证和回归
- 数据量级适中：足够展示能力，但不会导致LLM调用超时

| 容错降级 | LLM调用失败时回退到模板输出，保证演示不中断 |
