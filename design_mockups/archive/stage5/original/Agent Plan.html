乾策 STUDIO — agent workbench — PLAN · DRAFT 01

点开一个 agent 之后，去哪里？

在铺代码前，我把三条路线画出来摆在桌上：形态、交互模型、数据源处理、副手编排 —— 都有明确的取舍。你审一遍，确认或否决，我再动笔。

01前提假设 · 我先替你定的事

你答卷里有几个 "Decide for me"，我按银行客户经理真实使用节奏做了选择，理由写在后面。

ASSUMPTION · 1

同一个 agent 工作台，三个入口

入口要"兼顾"，但页面只做一份 —— 不管从 Agent tab 卡片点进、从今日看板 flight 条点进、还是从 IM @ 召唤，统一进同一个 agent workbench。区别只在入场动画的"来向"。

Agent tab →
下方整屏滑出
flight →
从 hero 那一行原地展开
IM @召唤 →
右侧 60% 抽屉滑出，IM 保留可见
ASSUMPTION · 2

交互模型：对话 + 就地改写（Cursor / Notion AI 式）

左侧对话区、右侧产出区。用户既可以打字命令 agent，也可以在产出上圈选一段文字 → 弹出"让 agent 改这里"菜单。不要做"一轮对话回一篇稿子"那种僵硬的 chatbot。

ASSUMPTION · 3

单 agent 主线，副手 agent 旁挂（小创新）

主 agent 在工作，另有一只"副手 agent"在后台读相关数据，只在它发现有用的东西时举手。例如：主 agent 在写额度建议稿，风控副手读到客户征信近期有新记录，就在侧边冒一条"注意：该客户 3 月新增一笔小额逾期"。

银行实际工作里这种"隐藏的第二只眼"非常重要，但大多数 AI 产品把它做成了"多个 chatbot 并列"，那种是错的 —— 太吵。我们做"默默盯着，有事才说话"。

ASSUMPTION · 4

数据源一定要展示

每段产出后挂一个折叠引用（默认折起来只显一个小圆标），点开看它引用了哪些系统 / 哪条客户档案 / 哪份产品说明。银行合规刚需，客户经理交材料时也需要溯源。

ASSUMPTION · 5

产出半编辑

直接在产出区光标编辑（像 doc），也可以圈选让 agent 改。不做"只读 + 复制导出"的假编辑器 —— 那是上一代产品的做法。

02三个方案 · 形态对比

方案不同之处主要在"页面的壳"—— 交互模型（对话+就地改写）、数据源引用、副手 agent 都是共用的。

A · 编辑部抽屉 B · 双页拉丝 C · 对话流 + 卡片岛
基调最保守平衡最有想法
页面占比右侧 62% 抽屉，shell 左侧露出一条"拼版台"全屏双栏 50/50，左 conversation 右 artifact全屏 IM-like 流，产出是可拖拽的"卡片岛"浮在流中
退出方式左划回 shell，产出自动归档到 Agent tab顶部面包屑回去，或 Esc一直存在，像抖音流一样滑动
对话 & 产出关系左右平行：左 chat，右 doc左右平行 + 关联线：对话某一条和产出某段有线连接，hover 高亮时间线：对话 → 产出卡片 → 对话 → 卡片 …… 顺序上下走
副手 agent顶部一排小铭牌，默默亮灯右上角"旁听席"，有话要说会冒气泡对话流里另一个头像插话（像群聊）
数据源引用产出段尾一个小圆码 ¹，点开浮层右侧 margin 列显示，像旁注卡片岛底部一条折叠带
编辑模式右侧产出区直接编辑；圈选弹菜单同 A，但有"diff 预览"叠层卡片内编辑，改动产生新卡片（版本堆）
最适合起草类任务（额度建议稿、晨会材料）分析+决策任务（画像、风险处置）轻量对话类（邀约话术、快速问答）
风险和现有 shell 太像，不够"agent 感"屏占多，小任务显得重长任务难定位；卡片堆叠后乱

我的推荐：A 和 C 各做一个样本 —— A 用「额度建议稿」（重型起草），C 用「客户邀约话术」（轻型对话）。B 的价值在"两边关联"这个细节，我打算把它作为共享组件放进 A / C 都用，而不单独做一个方案。这样 3 个方案变 2 个，但覆盖的维度一样多，深度更够。

03两个样本 agent

SAMPLE · A 承载

额度建议稿 · Credit Proposal

场景：客户经理要给某企业客户起草一份 5000 万授信建议稿，交给审贷会。

  • 输入：客户名 + 拟授信额度 + 用途 + 抵押物（可选）
  • 副手：风控副手（读征信 / 担保物 / 行业敞口）、合规副手（读最新产品规则）
  • 产出形态：正文（5 段）+ 数据表 + 结论表 + 附件清单
  • 数据源：客户档案 / CRS / 产品库 / 行业研报 / 同业对比
SAMPLE · C 承载

客户邀约话术 · Outreach Script

场景：客户经理临时要约三个客户喝茶，让 agent 按各自画像写三版邀约。

  • 输入：选客户（从联系人）+ 邀约目的 + 语气偏好
  • 副手：画像副手（抽最近一次互动、兴趣点、雷区）
  • 产出形态：三张"邀约卡片"并列 / 每张带 A/B 两版 / 一键复制到 IM
  • 数据源：客户档案 / 近期 IM 记录 / 日历

04小创新清单

在延续 shell 视觉的前提下，这些是我想塞进 agent 页的新东西：

  • 副手默默举手—— 不是聊天室，是"旁听 → 有事才说"。做成一个低调的"铭牌冒泡"。
  • 圈选改写—— 鼠标划一段文字，出一个小 ⌘ 浮条，两个选项：「让 agent 改」/「追问这段」。
  • 引用圆码—— 正文段尾 ¹ ² ³（mono 体，像学术论文），点开浮层展开原始数据片段。
  • 进度铭牌—— agent 执行时不是 loading spinner，而是像报纸头版那样一条 "正在读征信 · 打捞 2023 年度报告"的话梗，每个动作有话术。
  • 产出历史手风琴—— 每次 agent 重跑，旧版本折进右侧手风琴，不会丢。
  • 一张"桌面便签"—— 客户经理的临时想法、会议要点，直接贴在 agent 工作台角落，agent 能读到。
